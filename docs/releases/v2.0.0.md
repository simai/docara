# Docara 2.0.0

Release date: 2026-08-25

Docara 2.0.0 is the first stable release of the standalone Docara 2 product.
It compiles Markdown, validated JSON, exact-pinned SIMAI Framework assets, and
admitted Smart/design artifacts into a self-contained static site.

## Requirements

- PHP 8.2 or newer;
- Composer;
- a filesystem that supports the package ownership and atomic build checks.

## Install

```bash
mkdir /path/to/docara-engine
cd /path/to/docara-engine
composer require simai/docara:^2.0
php vendor/bin/docara init /path/to/empty-project
```

`init` accepts only an empty target. Continue from the generated project:

```bash
cd /path/to/empty-project
php /path/to/docara-engine/vendor/bin/docara doctor --json
php /path/to/docara-engine/vendor/bin/docara build production
php /path/to/docara-engine/vendor/bin/docara verify-static build_production
php /path/to/docara-engine/vendor/bin/docara serve production \
  --host=127.0.0.1 --port=8000 --no-build
```

## Highlights

- one Markdown owner for every public page;
- schema-validated site, section, and page settings with provenance;
- multilingual routing, navigation, search, backlinks, and component indexes;
- typed Document IR and one PageBuilder for complete and selected-page builds;
- native components, project-owned Smart artifacts, and declarative design;
- immutable local Framework assets without runtime CDN fallback;
- atomic builds and strict static-output verification;
- Developer/AI SDK, isolated previews, deterministic QA plans, and optional
  read-only MCP access;
- transactional engine updates with ownership checks and rollback packages;
- deterministic package archives with complete ledgers and CycloneDX SBOM.

## Breaking change from Docara 1.x

Docara 2 is a replacement architecture, not an in-place update of the former
Jigsaw/Mix product. Create a new Docara 2 project and migrate project-owned
Markdown, assets, and settings through an explicit migration plan.

Do not run `init` over an existing project. Do not use `init --update`.

## Updating a Docara 2 candidate project

After selecting the stable Composer version, preserve the engine consumer's
`composer.lock`, change to the site directory, and run:

```bash
php /path/to/docara-engine/vendor/bin/docara update --verify --json
php /path/to/docara-engine/vendor/bin/docara update --dry-run --json
# Review the exact plan before applying it.
php /path/to/docara-engine/vendor/bin/docara update --apply --json
php /path/to/docara-engine/vendor/bin/docara build production
php /path/to/docara-engine/vendor/bin/docara verify-static build_production
```

The update transaction may replace only package-owned `.docara/engine`
state. Content, assets, site configuration, locale files, Framework locks, and
the consumer's `composer.lock` remain project-owned.

## Rollback

```bash
php /path/to/docara-engine/vendor/bin/docara update --rollback=latest
php /path/to/docara-engine/vendor/bin/docara build production
php /path/to/docara-engine/vendor/bin/docara verify-static build_production
```

For a published site, retain the previously verified static directory and use
the hosting platform's atomic release switch. A successful build is not itself
a deployment.

## Verification

The release candidate is accepted only after:

- Composer validation, formatting, and the complete PHPUnit suite;
- documentation-site build and `verify-static`;
- byte-identical packages from two independent clean clones;
- fresh package-consumer install, init, build, static verification, update,
  and rollback checks;
- exact GitHub tag/release and Packagist readback.

## Known limitations

- No automatic migration from Docara 1.x is provided.
- Browser/visual QA and external hosting remain separate acceptance and
  deployment activities.
