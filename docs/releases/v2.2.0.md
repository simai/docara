# Docara 2.2.0

Release date: 2026-08-26

Docara 2.2.0 adds optional page-authoring profiles and page-aware SDK
operations. It helps people and AI agents create, inspect and validate pages
through the same project model without adding a second knowledge database or a
separate status engine.

## Requirements

- PHP 8.2 or newer;
- Composer;
- an existing Docara 2 project or an empty directory for `init`.

## Install or update

For a new engine installation:

```bash
composer require simai/docara:^2.2
```

For an existing Docara 2 project, update the Composer dependency and then use
the existing transactional engine update:

```bash
php /path/to/engine/vendor/bin/docara update --verify --json
php /path/to/engine/vendor/bin/docara update --dry-run --json
# Review the exact plan before applying it.
php /path/to/engine/vendor/bin/docara update --apply=<plan-sha256> --json
php /path/to/engine/vendor/bin/docara build production
php /path/to/engine/vendor/bin/docara verify-static build_production
```

Docara does not overwrite project Markdown, examples, assets, configuration,
translation locks or the engine consumer's `composer.lock`.

## Optional authoring contract

A project may add `docara.authoring.json` to select a default profile and map
content paths to one of six built-in profiles:

- `landing`;
- `article`;
- `tutorial`;
- `how_to`;
- `reference`;
- `explanation`.

An individual page may override the effective profile through the optional
front-matter field `profile`. Projects without this file and field keep their
previous behavior.

Profiles validate measurable structure and expose a semantic checklist for
editorial review. Docara does not call an AI service, grade prose quality or
edit authored content during validation.

## Page SDK

The existing SDK command families now understand physical Markdown pages:

```bash
php vendor/bin/docara list page --json
php vendor/bin/docara inspect page /ru/reference/cli/ --json
php vendor/bin/docara validate page /ru/reference/cli/
php vendor/bin/docara validate project
php vendor/bin/docara schema authoring --json
```

`inspect page` returns one machine-readable view of the page, including its
source, route, front matter, effective settings, profile, component and example
links, translation relation, revisions, hashes, provenance and diagnostics.
CLI and MCP consumers use the same application services and result contract.

New pages can be prepared through the existing hash-bound scaffold plan/apply
flow:

```bash
php vendor/bin/docara scaffold page /ru/guides/new-page/ \
  --locale=ru \
  --title="New page" \
  --profile=how_to \
  --dry-run \
  --json
```

Changing any bound input invalidates the prepared apply plan. Scaffold creates
only a missing Markdown file inside the configured locale content root.

## Compatibility and rollback

The release is backward compatible within Docara 2. Page profiles and the
authoring contract are opt-in. To roll back a project engine snapshot, use the
existing transactional rollback command and rebuild the static output:

```bash
php /path/to/engine/vendor/bin/docara update --rollback=latest
php /path/to/engine/vendor/bin/docara build production
php /path/to/engine/vendor/bin/docara verify-static build_production
```

A successful package or site build is not a public deployment.
