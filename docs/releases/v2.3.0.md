# Docara 2.3.0

Release date: 2026-08-29

Docara 2.3.0 prepares the exact SIMAI Framework resources required by each
generated page before the first paint. The browser receives final shell styles,
fonts, component dependencies and truthful Loader state without requiring a
project-specific preload list or `utility.full.css`.

## Requirements

- PHP 8.2 or newer;
- Composer;
- an existing Docara 2 project or an empty directory for `init`.

## Install or update

For a new engine installation:

```bash
composer require simai/docara:^2.3
```

For an existing Docara 2 project, update the Composer dependency and use the
transactional engine update flow:

```bash
php /path/to/engine/vendor/bin/docara update --verify --json
php /path/to/engine/vendor/bin/docara update --dry-run --json
# Review the exact plan before applying it.
php /path/to/engine/vendor/bin/docara update --apply=<plan-sha256> --json
php /path/to/engine/vendor/bin/docara build production
php /path/to/engine/vendor/bin/docara verify-static build_production
```

Docara does not overwrite project Markdown, examples, assets, configuration,
translation locks or the engine consumer's `composer.lock`.

## Automatic Framework asset planning

The production builder analyses final HTML through the Framework Loader rule
registry, resolves utility, component and Smart-component dependencies, and
emits content-addressed page CSS before rendering. JavaScript stays in its
declared dependency order, while `SF_PRELOADED` tells the dynamic Loader exactly
which modules are already complete.

Projects continue to use ordinary Framework markup. No new required project
setting, manifest or manual component list is introduced. Components added
later by dynamic content remain the responsibility of the existing Loader.

The bundled runtime is pinned to the published SIMAI Framework 5.4.0 release.
All CSS-local fonts and images referenced by the projected resources are
included in the same verified packet.

## Stable shell rendering

- local Inter and the active Material Symbols font are preloaded;
- the Inter fallback is metric-compatible and uses `font-display: optional`;
- fenced code renders its final header, copy control and scroll surface on the
  server before syntax highlighting becomes interactive;
- Framework menu and icon hydration preserves server-rendered geometry;
- the page shell remains visible while non-critical Framework modules load;
- normal document flow restores expected vertical margin collapsing;
- previous and next links use a quieter, compact presentation.

Static verification recalculates each page plan from final HTML and rejects
stale receipts, missing content-addressed assets, dependency reordering,
duplicate modules and false preload claims.

## Caching

Generated assets with content hashes are safe to serve with long-lived
immutable HTTP caching. HTML should remain revalidated so a new build can point
to new asset names. HTTP cache headers are configured by the hosting layer, not
by the static builder.

## Compatibility and rollback

The release remains compatible with Docara 2 projects. Projects without a
production-aware Framework registry fall back to the existing dynamic Loader
with a diagnostic warning.

To roll back an engine snapshot, use the transactional rollback command and
rebuild the static output:

```bash
php /path/to/engine/vendor/bin/docara update --rollback=latest
php /path/to/engine/vendor/bin/docara build production
php /path/to/engine/vendor/bin/docara verify-static build_production
```

A successful package or site build is not a public deployment.
