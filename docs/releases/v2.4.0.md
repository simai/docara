# Docara 2.4.0

Release date: 2026-08-30

Docara 2.4.0 adds an optional universal way to keep documentation aligned with
the public contract of the documented project. It does not add a second
catalogue, call AI, access the network or edit project documentation during
status checks and builds.

## Requirements

- PHP 8.2 or newer;
- Composer;
- an existing Docara 2 project or an empty directory for `init`.

## Install or update

For a new engine installation:

```bash
composer require simai/docara:^2.4
```

For an existing Docara 2 project, update the Composer dependency and use the
transactional engine update flow:

```bash
php vendor/bin/docara update --verify --json
php vendor/bin/docara update --dry-run --json
# Review the exact plan before applying it.
php vendor/bin/docara update --apply=<plan-sha256> --json
php vendor/bin/docara build production
php vendor/bin/docara verify-static build_production
```

## Source-backed documentation tracking

Projects may enable `documentation_tracking` and connect one or more exact
source contracts. The neutral `docara.documentation_source.v1` format supports
Framework entities as well as arbitrary entity kinds from other projects.

Docara reports whether each source entity is current, new, changed, missing,
missing an example, unverified, orphaned or intentionally excluded. The
accepted state stores only relations and fingerprints; public classes and
parameters remain owned by the source contract.

The same Application services power CLI and MCP operations:

```bash
php vendor/bin/docara list source --json
php vendor/bin/docara inspect source simai-framework:component.buttons --json
php vendor/bin/docara documentation status --json
php vendor/bin/docara validate project --json
```

Acceptance and source-aware scaffolding use reviewable hash-bound plans. Any
changed source contract, Markdown, example, configuration or lock invalidates
an unapplied plan.

## SIMAI Framework 5.4.1

The pinned runtime exposes 226 utility families, 63 ordinary components and 43
Smart Components. Its exact neutral documentation contract contains 334
entities, including Core design tokens and one source-owned recipe.

The contract distinguishes `--sf-radius--ui` for compact controls from
`--sf-radius-default` for large surfaces. Explicit `square` and `rounded`
modifiers continue to override the semantic default.

## Reusable examples

Example sandboxes now receive the exact Framework CSS, component scripts and
local icon-font resources planned for their own markup. Result tabs measure
their real content after those resources settle, avoiding persistent empty
space while preserving sandbox isolation and theme propagation.

## Compatibility and rollback

Projects without `documentation_tracking` retain their previous behavior.
Framework projects without a neutral contract continue through the read-only
compatibility adapter with a limited-accuracy diagnostic.

To roll back an engine snapshot, use the transactional rollback command and
rebuild the static output:

```bash
php vendor/bin/docara update --rollback=latest
php vendor/bin/docara build production
php vendor/bin/docara verify-static build_production
```

A successful package or site build is not a public deployment.
