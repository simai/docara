# Docara 2.5.0

Release date: 2026-08-31

Docara 2.5.0 makes compatible project updates a single verified operation and
publishes the installed package capabilities in a machine-readable contract.
It also records deterministic performance inputs for every production build
without imposing project-specific budgets.

## Requirements

- PHP 8.2 or newer;
- Composer;
- an existing Docara 2 project or an empty directory for `init`.

## Install

For a new project-local installation:

```bash
composer require simai/docara:^2.5
php vendor/bin/docara init .
```

Projects already using a project-local Composer runtime can check and apply the
highest compatible patch or minor update inside Docara 2:

```bash
php vendor/bin/docara upgrade --check --json
php vendor/bin/docara upgrade
```

The explicit command prepares a separate dependency candidate, runs `doctor`,
project validation, engine synchronization, a production build and
`verify-static`, then promotes the candidate only after every check passes.
The prior dependencies, engine and verified build remain available for an
offline compensating rollback:

```bash
php vendor/bin/docara upgrade --rollback=latest
```

Major updates are never applied automatically. Legacy projects without a
project-local Composer runtime receive a migration instruction and keep their
old engine intact.

## Machine-readable capabilities

```bash
php vendor/bin/docara capabilities --json
```

The result reports the exact Docara version and revision, AI contract, actual
CLI operations and parameters, schemas, SDK types, receipts, tracking and
lifecycle support. CLI and MCP use the same Application service. The canonical
Docara skill reads this contract, so one skill can work safely with different
Docara 2.x projects without copying the product command catalogue.

## Performance evidence and image geometry

Production builds write `.docara/performance.json` with deterministic per-page
request counts, transfer sizes, inline resource sizes and the largest shared
local assets. `verify-static` recomputes and hash-binds this report. Docara does
not turn these facts into a universal pass/fail budget; each project may apply
its own thresholds.

Ordinary Markdown images now remain inside the prose column, preserve their
intrinsic aspect ratio and do not stretch small sources. Declared media ratios
compile to real Framework `aspect-*` utilities, including the documented 21:9
compatibility rule.

## Compatibility and safety

- Projects without the new commands keep their existing build behavior.
- Normal builds remain offline; only an explicitly started `upgrade` may ask
  Composer for package metadata.
- Project Markdown, examples, assets, settings, Framework locks and translation
  state are never edited by `upgrade`.
- The existing low-level `update` flow remains available for package-owned
  engine synchronization.
- A successful package or site build is not a public deployment.
