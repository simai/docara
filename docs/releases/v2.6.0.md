# Docara 2.6.0

Release date: 2026-09-01

Docara 2.6.0 ships a local, content-addressed Material Symbols subset for the
documentation shell. The initial page no longer needs the 3.96 MB full icon
font, while icons added later still have exact package-owned fallbacks.

## Requirements

- PHP 8.2 or newer;
- Composer;
- an existing Docara 2 project or an empty directory for `init`.

## Install and upgrade

For a new project-local installation:

```bash
composer require simai/docara:^2.6
php vendor/bin/docara init .
```

Existing Docara 2 projects can check and apply the highest compatible patch or
minor release through the verified upgrade flow:

```bash
php vendor/bin/docara upgrade --check --json
php vendor/bin/docara upgrade
```

Docara validates the candidate, builds the site and runs `verify-static` before
it replaces the current runtime. User Markdown, examples, assets, settings and
Framework locks are not rewritten.

## Universal Framework icon subsets

- The documentation shell preloads a package-owned WOFF2 subset containing
  only the icons required for its first frame.
- The subset CSS, font, source font, generator inputs and hashes are recorded
  in the existing Framework build receipt.
- `verify-static` rejects a stale subset, an absent icon, a changed font,
  incorrect family metadata, false preload information and external `@latest`
  dependencies.
- Unknown icons can use the exact local full `outlined`, `rounded` or `sharp`
  font lazily. Normal Docara builds do not contact `icons.simai.io` or another
  network service.

The bundled runtime is bound to SIMAI UI Core 5.5.0. Projects carrying the
exact previous Framework 5.4.1 runtime lock remain readable and receive the
normal package-owned synchronization path; altered or ambiguous locks still
fail closed.

## Compatibility and safety

- Projects that do not use the new subset metadata keep their existing build
  behavior.
- The public CLI and `docara.ai_contract` command surface are unchanged, so the
  canonical Docara skill remains compatible.
- The full font is retained only as a local lazy fallback and is not loaded in
  the initial frame.
- A successful package or site build is not a public site deployment.
