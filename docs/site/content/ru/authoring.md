# Написание страниц

В Docara источник истины — файлы проекта. Markdown хранит текст и структуру
страницы, а JSON-файлы — настройки сайта, раздела и отдельной страницы.
Сборка создаёт из них HTML, индекс поиска и квитанции для проверки.

:::card
### Простое правило

Начинайте с обычного Markdown. Добавляйте JSON только для оформления и
навигации. Берите компонент только тогда, когда Markdown недостаточно, и
копируйте точный вызов со страницы компонента.

:::

## Путь автора

1. [Напишите страницу в Markdown](/ru/authoring/markdown/): заголовки,
   списки, ссылки, таблицы, код и метаданные страницы.
2. [Расставьте страницы в меню](/ru/authoring/navigation/): разделы, порядок,
   скрытые страницы и верхнее меню.
3. Для нескольких языков соберите
   [мультиязычный сайт](/ru/authoring/multilingual-site/).
4. При изменении адреса страницы
   [объявите перенаправление](/ru/authoring/redirects/).
5. При желании включите проверку
   [профилей страниц](/ru/authoring/page-profiles/) и
   [актуальности документации](/ru/authoring/documentation-tracking/).
6. Если Markdown недостаточно, [найдите компонент](/ru/components/).
7. Настройте внешний вид в разделе [«Настройка сайта»](/ru/settings/) и
   [соберите и проверьте результат](/ru/build/verify/).

## Не редактируйте результат сборки

`build_*`, квитанции в `build_*.docara/` (`resolved-page-plans.json`,
`redirects.json` и другие) и `_docara/component-catalog.json` создаются
заново при каждой сборке. Если результат неверен, исправьте исходный Markdown
или JSON и повторите сборку.

## Документация и лендинг

Оба вида страниц — документация (`docs`) и лендинг (`landing`) — используют
один формат содержимого, одну версию SIMAI Framework и одни правила
безопасности. Отличается только оформление: документационная страница с меню и
содержанием или сфокусированная страница без них. Подробнее — в разделе
[«Области макета»](/ru/settings/layout-and-regions/).
