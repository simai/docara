# Markdown

Страница Docara — это обычный файл Markdown. Начинайте её с одного заголовка
H1, дальше используйте H2–H6, абзацы, списки, ссылки, изображения, цитаты, код,
таблицы и сноски. Компонент нужен только там, где Markdown недостаточно.

```markdown
# Установка

Коротко объясните результат страницы.

## Шаги

1. Установите пакет.
2. Инициализируйте сайт.

| Команда | Результат |
| --- | --- |
| `docara build production` | Статический production-каталог |
```

## Метаданные страницы

Перед H1 можно добавить блок метаданных (front matter) между строками `---`:

```markdown
---
title: Установка
description: Подготовьте первый сайт Docara.
tags: [start, install]
draft: false
translation_key: guide.install
---

# Установка
```

Блок принимает только эти ключи; любой другой останавливает сборку с
[`FRONT_MATTER_KEY_UNKNOWN`](/ru/reference/errors/content/#заголовок-страницы-front-matter):

- `title` и `description` — заголовок и описание страницы;
- `tags` — список в одну строку, например `tags: [деплой, публикация]`; по
  меткам страницу находит [поиск](/ru/settings/search/#синонимы-метки-страницы);
- `draft` — `true` или `false`; черновик не публикуется, и его нельзя собрать
  как public `--page`;
- `noindex` — `true` или `false`; `true` публикует страницу, но добавляет
  `<meta name="robots" content="noindex">` и убирает её из `sitemap.xml` и
  `llms.txt` (см. [адрес сайта](/ru/settings/site-address/)). Поиск по сайту
  настраивается отдельно: `"search": {"indexed": false}` в `<route>.page.json`;
- `translation_key` — стабильный ключ, который связывает переводы одной
  страницы;
- `profile` — встроенный [профиль проверки](/ru/authoring/page-profiles/):
  `landing`, `article`, `tutorial`, `how_to`, `reference` или `explanation`;
- `composition_recipe` — путь к JSON-дескриптору Composition Recipe
  относительно проекта; пример — страница
  [Composition Recipe: расширенная шапка](/ru/examples/composition-recipe-expanded/).

Макет, HTML и произвольные поля в метаданных запрещены. Ошибка в блоке
указывает исходный файл, строку и колонку. Остальные настройки страницы
задаются в соседнем файле `<page>.page.json` — см.
[«Сайт, раздел и страница»](/ru/settings/levels-and-inheritance/).

## Заголовки и текст

Заголовки делят статью на понятные разделы, а обычный Markdown выделяет
важные слова без ручной HTML-разметки.

:::example {label="Заголовки и выделение"}
```markdown
## Настройка проекта

Сначала укажите **обязательные параметры**, затем добавьте *полезные
пояснения*. Устаревшую рекомендацию можно временно отметить как
~~неактуальную~~.
```
:::

| Запись | Назначение |
| --- | --- |
| `#` | Название страницы; используется один раз |
| `##` | Основной раздел |
| `###` | Подраздел внутри основного раздела |
| `####`–`######` | Редкая дополнительная детализация |

Не пропускайте уровни только ради размера шрифта: внешний вид задаёт тема, а
уровень описывает структуру документа.

```markdown
**важный текст**
*смысловой акцент*
~~устаревшая формулировка~~
`имя_параметра`
```

Жирное начертание подходит для ключевого результата, курсив — для короткого
акцента, зачёркивание — для явно устаревшей формулировки, а inline-код — для
команд, файлов и значений. Произвольный HTML вместо Markdown не используйте.

Заголовки получают детерминированные якоря, по которым на них можно сослаться;
как строится якорь, описано в разделе
[«Контекст чтения»](/ru/settings/reading/#как-формируются-якоря). При
переименовании заголовка меняется адрес фрагмента, поэтому после правки
повторяйте `verify-static`.

## Списки и цитаты

Списки показывают набор или последовательность действий, а цитата отделяет
точную внешнюю формулировку от авторского текста.

:::example {label="Список и цитата"}
```markdown
1. Проверьте конфигурацию.
2. Соберите документацию.
3. Откройте готовую страницу.

> Хорошая документация помогает выполнить задачу.
```
:::

Используйте маркированный список, когда порядок не важен:

- краткое назначение;
- допустимые параметры;
- полезные ограничения.

Нумерованный список подходит для последовательности:

1. Подготовьте Markdown.
2. Запустите сборку.
3. Проверьте ссылки и внешний вид.

Вложенные пункты отделяют детали, но не должны превращать страницу в сложное
дерево.

У цитаты можно указать источник:

> Сначала определите задачу читателя, а затем объясняйте устройство системы.
{author="Автор материала" source="Название источника" href="https://example.com/source"}

```markdown
> Сначала определите задачу читателя, а затем объясняйте устройство системы.
{author="Автор материала" source="Название источника" href="https://example.com/source"}
```

Параметр `author` называет автора, `source` — публикацию, а `href` добавляет
безопасную ссылку. Не заполняйте неизвестные реквизиты заглушками: обычная
цитата без подписи полезнее выдуманного источника.

## Ссылки и изображения

Ссылки ведут читателя к следующему полезному шагу, а изображения дополняют
текст понятным визуальным объяснением и доступным описанием.

:::example {label="Ссылка и изображение"}
```markdown
[Открыть каталог компонентов](/ru/components/)

![Знак Docara](../../assets/docara-mark.svg)
```
:::

Используйте понятную подпись, по которой видно назначение перехода:

- [прочитать быстрый старт](/ru/start/quick-start/);
- [открыть страницу обратных ссылок](/ru/components/backlinks/);
- [посмотреть репозиторий Docara](https://github.com/simai/docara).

Не заменяйте смысл подписи словами «нажмите здесь». Для страниц сайта
используйте пути от корня сайта, для картинок — относительные пути к файлам
проекта. `base_url` генератор добавляет сам там, где это предусмотрено.
Небезопасные протоколы отклоняются.

![Знак Docara в рамке 16:9](../../assets/docara-icon.svg){ratio=16/9 fit=contain}

| Параметр | Значения | Назначение |
| --- | --- | --- |
| `ratio` | `auto`, `1/1`, `4/3`, `3/2`, `16/9`, `21/9` | Форма области изображения |
| `fit` | `cover`, `contain` | Обрезать до заполнения или показать целиком |

```markdown
![Страница с иллюстрацией](../../assets/markdown-scene.webp){ratio=16/9 fit=contain}
```

Альтернативный текст должен передавать назначение изображения. Декоративную
картинку не используйте вместо заголовка или инструкции. Картинку с подписью и
заданными пропорциями даёт компонент [«Иллюстрация»](/ru/components/figure/).

## Таблицы

Таблица компактно сравнивает несколько объектов по одинаковым признакам и на
узком экране прокручивается внутри своей области.

:::example {label="Таблица"}
```markdown
| Файл | Роль |
| --- | --- |
| `docara.json` | Настройки сайта |
| `section.json` | Настройки раздела |
| `.page.json` | Настройки одной страницы |
```
:::

Таблица полезна для параметров, совместимости и коротких сравнений. Если в
ячейках появляются длинные абзацы или вложенные списки, обычные разделы будут
понятнее.

| Возможность | Полная сборка | Одиночная сборка | Результат |
| --- | --- | --- | --- |
| Markdown | Все выбранные страницы | Один выбранный route | HTML |
| Проверка ссылок | Весь сайт | Сохранённый полный контекст | 0 broken |
| Навигация | Общий порядок | Тот же порядок | Одинаковые переходы |

Первая строка задаёт заголовки столбцов, вторая — разделители. Это обычная
таблица Markdown, а не контракт для сложного интерактивного представления
данных.

## Код

Блок кода в тройных обратных кавычках остаётся читаемым статическим
`<pre><code>`, а закреплённый SIMAI Framework добавляет заголовок с языком,
доступную кнопку копирования, подсветку синтаксиса и прокрутку длинных строк.
Копируется только точное содержимое `<code>`, без интерфейса. Если словарь
языка недоступен, код остаётся безопасным читаемым текстом. Параметры блока
кода и вставка фрагмента из файла проекта описаны на страницах
[«Код»](/ru/components/code/) и [«Код из файла»](/ru/components/code-from-file/).

Внутри обычного блока кода строки директив остаются текстом и безопасно
показываются читателю — так можно показать вызов компонента:

````markdown
```markdown
:::ui.<component>
{"<prop>":"<value>"}
:::
```
````

## Сноски и источники

Сноска добавляет проверяемое пояснение или источник, не прерывая основной
текст. Читатель переходит к примечанию и может вернуться к месту ссылки.

:::example {label="Сноска"}
```markdown
Docara собирает документацию из Markdown.[^source]

[^source]: Руководство проекта, актуальная версия и адрес публикации.
```
:::

Метка между `[^` и `]` должна быть короткой и устойчивой: `source`, `api` или
номер. Одна метка связывает ссылку в тексте с одним определением ниже.

| Часть | Назначение |
| --- | --- |
| `[^source]` | Ссылка в основном тексте |
| `[^source]: ...` | Текст примечания или описание источника |
| Адрес публикации | Позволяет читателю проверить утверждение |

Сноска не заменяет понятный основной текст. Указывайте автора, название,
версию или дату и доступный адрес, если утверждение опирается на внешний
источник.

## Когда нужен компонент

Raw HTML удаляется. Если обычного Markdown недостаточно:

1. откройте [каталог компонентов](/ru/components/);
2. выберите запись со статусом `supported`;
3. скопируйте точный вызов со страницы компонента;
4. пересоберите и проверьте сайт.

Для оформленной полосы используйте [Surface](/ru/components/surface/), а для
первого экрана — [Hero](/ru/components/hero/). Hero, Showcase и Promo уже
используют общее оформление Surface: не вкладывайте их в Surface и не
добавляйте CSS, путь к шаблону или отдельный фон.

Не копируйте параметры компонента из старой страницы или другого проекта:
точный контракт принадлежит каталогу компонентов текущей сборки, а объяснение —
странице компонента. Общая модель описана на странице
[«Как устроены компоненты»](/ru/start/component-model/).

## Проверка

```bash
php vendor/bin/docara build production
php vendor/bin/docara verify-static build_production
```

`verify-static` найдёт ссылку на отсутствующую страницу или якорь, повторяющийся
HTML `id` и неправильную кодировку фрагмента.
