# Профили страниц

Профиль говорит, какого типа страница: инструкция, справочник, лендинг и так
далее. По профилю `docara validate page` проверяет, есть ли у страницы нужные
части, например нумерованные шаги у инструкции, и выдаёт список вопросов для
редактора. Проверка ничего не меняет в Markdown, не обращается к ИИ и не
останавливает сборку.

Профили необязательны. Без файла `docara.authoring.json` и без `profile` во
front matter страницы не проверяются, и сборка ничего нового не пишет. Новый
проект из `docara init` получает этот файл сразу, вместе с каркасом страниц по
типам и файлом `AGENTS.md` для ИИ-помощников.

## Файл `docara.authoring.json`

Файл лежит в корне проекта рядом с `docara.json`:

```json
{
  "schema": "docara.authoring.v1",
  "default_profile": "article",
  "rules": [
    {"match": "index.md", "profile": "landing"},
    {"match": "start.md", "profile": "tutorial"},
    {"match": "reference/**", "profile": "reference"},
    {"match": "development/architecture.md", "profile": "explanation"}
  ]
}
```

| Поле | Что задаёт |
| --- | --- |
| `schema` | Тип файла. Всегда `docara.authoring.v1`. |
| `default_profile` | Профиль страниц, которым не подошло ни одно правило. Без него профиль таких страниц угадывается, см. [Если профиль не задан](#если-профиль-не-задан). |
| `infer_profiles` | `false` выключает угадывание профиля. По умолчанию `true`. |
| `rules` | Правила: какой профиль у страниц по пути. |
| `rules[].match` | Путь к файлу страницы от каталога языка, например `reference/cli.md`. `*` заменяет часть имени внутри одного каталога, `**` — любое число каталогов, `?` — один символ. |
| `rules[].profile` | Профиль для подошедших страниц. |
| `audiences` | Список читателей сайта, например `["reader", "author"]`. Сейчас только проверяется на формат и на результат не влияет. |

Если странице подходят два правила с разными профилями, проверка
остановится с `AUTHORING_RULE_CONFLICT`. Уточните пути, чтобы у каждой
страницы был один профиль.

## Профиль в front matter

Профиль одной страницы можно задать прямо в ней. Он важнее правил из
`docara.authoring.json`:

```markdown
---
profile: how_to
---

# Как опубликовать сайт
```

## Профили и что они проверяют

| Профиль | Для чего | Что должно быть на странице |
| --- | --- | --- |
| `landing` | Вход в раздел и призыв к действию | Один заголовок `#`, вступление, не меньше двух разделов `##`, ссылка или блок |
| `article` | Связный рассказ об одной теме | Один заголовок `#`, вступление, хотя бы один раздел `##` |
| `tutorial` | Обучение на примере от начала до результата | Один заголовок `#`, нумерованный список хотя бы из двух шагов |
| `how_to` | Решение одной практической задачи | Один заголовок `#`, нумерованный список хотя бы из двух шагов |
| `reference` | Точные сведения для поиска | Один заголовок `#`, вступление, таблица, список, код или блок |
| `explanation` | Причины, устройство и ограничения | Один заголовок `#`, вступление, хотя бы один раздел `##` |

Если части не хватает, `docara validate page` сообщает код
`PAGE_PROFILE_<ЧАСТЬ>_MISSING`, например `PAGE_PROFILE_ORDERED_STEPS_MISSING`.
Каждая проверенная страница также получает `PAGE_EDITORIAL_REVIEW_REQUIRED` —
список смысловых вопросов для редактора, на которые программа не отвечает.

```bash
php vendor/bin/docara validate page /ru/start/ --json
```

После `docara build` сборка печатает, сколько страниц требуют внимания, но
сайт всё равно собирается.

## Если профиль не задан

Если странице не подошли ни front matter, ни правило, ни `default_profile`,
Docara угадывает профиль по пути и тексту. Правила проверяются по порядку,
срабатывает первое:

| Признак | Профиль |
| --- | --- |
| Файл `index.md` в любом каталоге | `landing` |
| Каталог или имя файла: `tutorial`, `getting-started`, `quickstart`, `learn` | `tutorial` |
| Каталог или имя файла: `how-to`, `howto` | `how_to` |
| Каталог или имя файла: `reference`, `api`, `glossary` | `reference` |
| Каталог или имя файла: `explanation`, `concepts`, `architecture` | `explanation` |
| Не меньше трёх нумерованных шагов | `how_to` |
| Таблицы, списки и определения — не меньше 60% строк текста | `reference` |
| Всё остальное | `article` |

Угаданный профиль — только подсказка. `docara validate page` показывает его
кодом `PAGE_PROFILE_INFERRED` с причиной, а недостающие части — с пометкой
`advisory`. Сборка их не считает и не останавливается. Если тип угадан верно,
впишите `profile:` во front matter. Чтобы выключить угадывание, добавьте в
`docara.authoring.json` строку `"infer_profiles": false`.

Угадывание работает, только когда в проекте есть `docara.authoring.json`.
Так старые сайты без этого файла собираются как раньше.

## Шаблоны страниц

`docara scaffold page` создаёт страницу нужного типа: с front matter, местом
для `description` и разделами этого типа.

```bash
php vendor/bin/docara scaffold page --type=how_to --title="Как сменить ключи"
php vendor/bin/docara scaffold page guides/install --type=tutorial --title="Установка"
```

Без адреса страница попадает в каталог своего типа, если он есть
(`getting-started/`, `how-to/`, `reference/`, `explanation/`), а имя файла
получается из заголовка. Текст шаблона пишется на языке основной локали:
русском или английском, для других языков — английский. Страница создаётся
с `draft: true`: замените текст-подсказки и удалите эту строку, чтобы
страница попала на сайт. С `--dry-run` команда только готовит план, как для
Smart-компонентов.

## Инструкция для ИИ-помощников

`docara init` кладёт в корень проекта `AGENTS.md`. Этот файл читают многие
ИИ-помощники для программирования. В нём описаны проект, типы страниц и их
обязательные части, правила текста, команда для новой страницы и проверки,
которые нужно пройти перед завершением работы. Файл можно править.

Если `AGENTS.md` уже есть, `init` его не трогает и пишет инструкцию в
`docs/AGENTS.docara.md`. Сошлитесь на неё из своего `AGENTS.md`.

Тот же стандарт отдают `docara capabilities --json` (поле
`documentation_standard`) и MCP-инструмент `docara_authoring_standard`.

## Ошибки файла

| Код | Причина и что сделать |
| --- | --- |
| `AUTHORING_JSON_INVALID` | Файл не является корректным JSON. **Что сделать:** Исправьте синтаксис. |
| `AUTHORING_SCHEMA_INVALID` | В файле не объект. **Что сделать:** Начните файл с `{"schema": "docara.authoring.v1", ...}`. |
| `SCHEMA_VALIDATION_FAILED` | Неизвестное поле, неверный профиль или путь в `match` с `/` в начале или `..`. **Что сделать:** Сверьте файл с таблицей выше. |
| `AUTHORING_FILE_UNSAFE` | Файл — символическая или жёсткая ссылка. **Что сделать:** Замените его обычным файлом. |
| `AUTHORING_RULE_CONFLICT` | Странице подходят правила с разными профилями. **Что сделать:** Уточните пути в `match`. |
| `AUTHORING_PROFILE_UNKNOWN` | Неизвестный профиль. **Что сделать:** Используйте один из шести профилей. |
