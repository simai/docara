# Воспроизводимость

При одинаковых Markdown, JSON, Framework lock и версии генератора повторная
сборка должна создавать байт-в-байт одинаковый результат.

Docara не записывает в portable output текущую дату и абсолютные локальные
пути. `_docara/page-metadata.json` использует историю Git exact source, если она
доступна; в Composer dist без `.git` поля `updated_at`, `revision` и `author`
равны `null`. Время распаковки или изменения файла не попадает в публичный
результат. Для каждой страницы квитанция `build_production.docara/resolved-page-plans.json`
содержит:

- итоговую конфигурацию;
- упорядоченный trace входных файлов с SHA-256;
- provenance каждого значения;
- canonical hash плана;
- нормализованные вызовы компонентов;
- точный asset plan;
- output path и публичный URL.

Для проверки соберите сайт дважды в чистые каталоги и сравните хэши деревьев.
Изменение входа или lock должно объяснимо изменить соответствующий план.

Если поиск включён, `content_sha256` в `_docara/search-index.json` вычисляется
из canonical documents, а query revision `_docara/search.js` — из точных байтов
runtime. Поэтому изменение содержания и изменение поискового кода инвалидируют
кэш независимо и остаются воспроизводимыми.

CSS постоянного каркаса собирается из зафиксированных Framework-ресурсов и
`declarative-shell.css`: каждый исходный файл публикуется один раз как
`docara-shell.<sha256>.css`, и имя определяется точными байтами файла.
Framework shell receipt фиксирует для каждой страницы входы, порядок
подключения, предзагруженные модули и hash каждого файла, поэтому одинаковая
сборка получает те же имена, а любое содержательное изменение — новое.

Если настроены redirects, квитанция `redirects.json` аналогично фиксирует
canonical records, SHA-256 канонически нормализованного source, locale, версию
документации и `base_url`. Форматирование и порядок записей во входном JSON не
меняют результат сборки.
