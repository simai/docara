# Размещение на хостинге

Результат `build production` — обычный набор статических файлов. Любой
статический хостинг отдаёт каталог `build_production/` как есть: nginx,
Apache, GitHub Pages, Netlify, S3-совместимое хранилище с веб-доступом и
другие. PHP, Composer и Node.js на сервере не нужны; они нужны только там, где
сайт собирается.

## Перед загрузкой

Соберите и проверьте именно тот каталог, который будете загружать:

```bash
php vendor/bin/docara build production
php vendor/bin/docara verify-static build_production
```

`verify-static` не выполняет проектный PHP-код и проверяет статический
каталог: страницы из manifest и физические HTML-файлы, локальные ссылки и
`#fragment`, уникальность HTML `id`, ассеты, поисковый индекс, resolved page
plans, страницы redirects, каталог компонентов, проекцию SIMAI Framework и
receipts сборки. При ненулевом exit code каталог не загружайте. Подробности —
в разделе [Проверка статического результата](/build/verify/).

Загружайте содержимое `build_production/` целиком и без изменений. Квитанции
сборки лежат рядом, в `build_production.docara/`, и на хостинг не загружаются:
посетителю они не нужны. Не
открывайте страницы через `file://`: так не работают pretty routes, `base_url`,
поиск и загрузка ассетов. Для локального просмотра используйте
`serve production --no-build`.

## Маршруты

Каждая страница — каталог с `index.html`: маршрут `/guides/install/`
соответствует файлу `guides/install/index.html`. Хостинг должен отдавать
`index.html` для запроса каталога. Большинство статических хостингов делает
это по умолчанию.

nginx:

```nginx
server {
    root /var/www/docs/current;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}
```

Apache (`.htaccess` или конфигурация виртуального хоста):

```apache
DirectoryIndex index.html
```

## Размещение в подкаталоге

Если сайт открывается не с корня домена, а, например, по адресу
`https://example.com/docs/`, задайте `base_url` в `docara.json` до сборки:

```json
{
  "base_url": "/docs/"
}
```

Docara строит все ссылки, ассеты и поиск с этим префиксом, а `verify-static`
проверяет каталог относительно него. Ссылки, которые автор пишет от корня
сайта, — `[Быстрый старт](/start/)` в Markdown, `href` пунктов
`header_navigation`, адрес внутреннего превью, изображение
`![Схема](/ru/guide/scheme.png)`, `srcset`, `poster` видео — сборка тоже
дополняет префиксом, поэтому один и тот же контент собирается и для корня домена, и для
подкаталога. Загрузите содержимое `build_production/`
в каталог, который сервер отдаёт по `/docs/`. Не исправляйте ссылки вручную
после сборки. Для сайта проекта на GitHub Pages адрес обычно имеет вид
`https://<owner>.github.io/<repository>/`, поэтому `base_url` равен
`"/<repository>/"`.

## Redirects

Записи из `redirects.json` превращаются в обычные HTML-страницы по старому
адресу: `old/route/index.html` содержит canonical, `noindex`, meta refresh и
видимую ссылку на новую страницу. Настраивать redirects на сервере не нужно.
Если хостинг умеет отдавать HTTP 301, такие правила можно добавить отдельно,
но статические страницы redirects остаются в каталоге. Формат файла описан в
разделе [Redirects](/authoring/redirects/).

## Страница 404

Сборка кладёт в корень сайта (под `base_url`) файл `404.html`: страницу
«Страница не найдена» с обычной шапкой, навигацией, поиском и темой сайта. На
ней заголовок, короткое пояснение, ссылка на главную страницу и ссылка,
которая открывает поиск (без JavaScript она ведёт на главную). Текст берётся
на основном языке сайта (`default_locale`); у Docara есть русский и
английский варианты.

Сервер отдаёт эту страницу по любому несуществующему адресу, например
`/ru/a/b/c/`. Поэтому все ссылки, стили, скрипты и поисковый индекс на ней
адресуются от корня сайта с учётом `base_url`, без относительных путей, и
страница одинаково работает на любой глубине.

Страница не попадает в поисковики и в структуру сайта: у неё
`<meta name="robots" content="noindex">`, её нет в навигации, поиске,
`sitemap.xml`, `llms.txt` и `_docara/page-metadata.json`.

### Как включить на хостинге

Сервер должен отдавать `404.html` для отсутствующих адресов и сохранять код
ответа 404.

- **nginx:**

  ```nginx
  server {
      root /var/www/docs/current;
      index index.html;
      error_page 404 /404.html;

      location / {
          try_files $uri $uri/ =404;
      }
  }
  ```

- **Apache** (`.htaccess` или конфигурация виртуального хоста):

  ```apache
  ErrorDocument 404 /404.html
  ```

- **GitHub Pages** отдаёт `404.html` из корня сайта сам, настраивать ничего не
  нужно. Netlify делает так же.
- **S3-совместимое хранилище:** в настройках статического сайта укажите
  error document `404.html`.

Для сайта в подкаталоге добавьте к пути `base_url`, например
`/docs/404.html` вместо `/404.html` в nginx и Apache.

### Свой текст

Подписи страницы — ключи `error.not_found.*` в `lang.json` основного языка:

```json
{
  "schema": "docara.lang.v1",
  "version": 1,
  "error": {
    "not_found": {
      "title": "Страница не найдена",
      "message": "Возможно, страницу перенесли. Начните с главной или поиска.",
      "home": "На главную",
      "search": "Искать в документации"
    }
  }
}
```

Чтобы заменить содержимое целиком, создайте страницу `404.md` в корне контента
основного языка, например `content/ru/404.md`. Это обычный Markdown с front
matter и компонентами; сборка публикует его как `404.html` вместо
`/ru/404/`, добавляет `noindex`, убирает страницу из навигации и поиска и
отключает на ней хлебные крошки, содержание и ссылки «Предыдущая/Следующая».
Ссылки на главную и поиск в такой странице пишите сами. Ссылка с адресом
`#docara-search` открывает поиск, как на встроенной странице; без JavaScript
или на сайте без поиска она ведёт на главную
(см. [Локальный поиск](/authoring/search/#ссылка-которая-открывает-поиск)):

```markdown
# Такой страницы нет

Проверьте адрес, начните с [главной страницы](/ru/) или
[откройте поиск](#docara-search).
```

Ссылки пишите от корня сайта (`/ru/start/`), сборка добавит `base_url`.
Относительные ссылки и изображения сборка тоже переводит в адреса от корня,
считая, что страница лежит по адресу `/ru/404/`.

### Как отключить

```json
{
  "not_found": {
    "enabled": false
  }
}
```

Без страницы сборка такая же, как до появления `404.html`: файла нет, а
`404.md`, если он есть, публикуется как обычная страница `/ru/404/`.

### Несколько языков и портал

На сайт приходится одна страница `404.html` на основном языке: сервер отдаёт
один файл для всех отсутствующих адресов. Отдельных `/en/404.html` для других
языков Docara не делает; файл `content/en/404.md` остаётся обычной страницей
`/en/404/` и в `sitemap.xml` не попадает.

Портальная сборка `404.html` не создаёт: этот файл принадлежит порталу. Если в
ней задать `"not_found": {"enabled": true}`, сборка остановится с
`PORTAL_NOT_FOUND_PAGE_FORBIDDEN`. Подробнее — в разделе
[Сборка для портала](/build/portal/).

## Кеширование

Общие ресурсы сборки публикуются один раз в `<base_url>_docara/`. Файлы, у
которых SHA-256 или ревизия входит в путь, при изменении получают новый адрес,
поэтому их можно кешировать надолго:

- `_docara/docara-shell.<sha256>.css` — общие для страниц стили каркаса,
  в среднем 4–6 файлов на страницу;
- `_docara/brand/<sha256>.*`;
- `_docara/vendor/simai-framework/runtime/<revision>/**`.

Для них подходит `Cache-Control: public, max-age=31536000, immutable`.
HTML-страницы и остальные файлы `_docara/` без хеша в пути, например
`_docara/search-index.json` и `_docara/search.js`, отдавайте без `immutable`,
с проверкой актуальности по `ETag` или `Last-Modified`. Страницы подключают
часть ресурсов с параметром версии (`?docara_v=…`, `?sf_v=…`), поэтому CDN
должен учитывать query string в ключе кеша.

```nginx
location ~ ^/_docara/(docara-shell\.[0-9a-f]{64}\.css$|brand/[0-9a-f]{64}\.|vendor/simai-framework/runtime/) {
    add_header Cache-Control "public, max-age=31536000, immutable";
}
```

Для сайта в подкаталоге добавьте префикс `base_url` в начало выражения.

## Особенности площадок

- **GitHub Pages.** При публикации через GitHub Actions
  (`actions/upload-pages-artifact`) загрузите `build_production/` как
  артефакт. При публикации из ветки положите в её корень пустой файл
  `.nojekyll`: иначе Jekyll пропустит каталог `_docara/`, имя которого
  начинается с подчёркивания.
- **Netlify и похожие сервисы.** Укажите `build_production` как publish
  directory. Если сборка выполняется на стороне сервиса, в его окружении нужны
  PHP 8.2+, Composer и Node.js 20+; проще собрать и проверить сайт в CI и загрузить
  готовый каталог.
- **S3-совместимое хранилище.** Включите режим статического сайта с index
  document `index.html`, чтобы адреса каталогов открывали страницы. Если
  хранилище закрыто CDN, проверьте, что CDN тоже отдаёт `index.html` для
  вложенных маршрутов.

## После загрузки

Откройте корень сайта и вложенную страницу, проверьте стили, поиск, ссылку с
`#fragment` и одну страницу redirect. Откройте несуществующий адрес на
нескольких уровнях вложенности: сервер должен ответить кодом 404 и показать
страницу `404.html` со стилями и поиском. Порядок с промежуточным каталогом,
digest и возвратом к предыдущей версии описан в разделе
[Публикация и rollback](/build/publish/).
