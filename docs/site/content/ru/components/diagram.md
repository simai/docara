# Диаграмма

Диаграмма хранит схему Mermaid рядом с текстом статьи, а браузер рисует её
как картинку. Схема меняется вместе с документацией: её исходник лежит в той
же странице и проверяется на ревью как обычный текст.

## Как вставить схему

Напишите блок `:::diagram`, укажите движок и понятное название, а внутри —
схему в записи Mermaid:

```markdown
:::diagram {engine=mermaid title="Публикация документации"}
flowchart LR
  Author[Автор] --> Build[Сборка]
  Build --> Verify[Проверка]
  Verify --> Publish[Публикация]
:::
```

Первая строка схемы называет её тип: `flowchart`, `sequenceDiagram`, `gantt`
и так далее. Подписи держите короткими — длинный текст делает схему широкой.

## Параметры

| Параметр | Что задаёт |
| --- | --- |
| `engine` | Движок схемы. Сейчас поддерживается только `mermaid`; его можно не указывать |
| `title` | Название схемы над ней. Его же слышит читатель с программой чтения с экрана, поэтому формулируйте его так, чтобы смысл был понятен без картинки |

## Какие схемы поддерживаются

Docara не ограничивает тип схемы: работает всё, что умеет встроенный
Mermaid 11.16. Мы проверили в браузере 22 типа — все они собраны с живыми
примерами в [«Галерее диаграмм»](/ru/components/diagram-gallery/).

| Задача | Типы Mermaid |
| --- | --- |
| Процесс и поведение | `flowchart` — шаги и развилки, `sequenceDiagram` — обмен запросами, `stateDiagram-v2` — состояния объекта, `journey` — путь пользователя |
| Структура и данные | `classDiagram` — классы кода, `erDiagram` — модель данных, `requirementDiagram` — требования, `mindmap` — интеллект-карта, `treemap-beta` — доли вложенных частей, `block-beta` — блоки по сетке, `packet-beta` — поля пакета |
| Архитектура | `C4Context` — контекст системы, `architecture-beta` — сервисы и группы |
| Планы и история | `gantt` — задачи на календаре, `timeline` — хронология, `gitGraph` — ветки Git, `kanban` — доска задач |
| Графики и сравнение | `pie` — доли целого, `xychart-beta` — столбцы и линии, `quadrantChart` — четыре группы по двум осям, `sankey-beta` — потоки, `radar-beta` — сравнение по оценкам |

Типы с окончанием `-beta` Mermaid пока считает экспериментальными: их запись
может немного измениться в следующих версиях.

## Особенности подписей и ограничения

- **`sankey-beta` не рисуется с русскими подписями** — ни с кавычками, ни без
  них. Пишите подписи потоков латиницей.
- **`architecture-beta` и `xychart-beta` принимают русские подписи только
  в двойных кавычках:** `service web(server)["Веб-сервер"]`,
  `x-axis ["Главная", "Значки"]`.
- **В `erDiagram` русские названия сущностей задаются псевдонимом** в блоке
  сущности: `PAGE["Страница"] { … }`, а связи пишутся через латинское имя.
- **Ссылки и обработчики щелчков в схемах не работают.** Mermaid запускается
  в строгом режиме безопасности, поэтому `click` и `href` внутри схемы
  игнорируются. Ссылку поставьте в тексте рядом со схемой.
- **ZenUML не входит в комплект**, схемы `zenuml` не рисуются.
- **Mermaid весит около 3,6 МБ.** Он загружается один раз на странице, сколько
  бы схем на ней ни было, и только на страницах со схемами.

## Примеры

### Блок-схема

:::example {label="Схема"}
```markdown
:::diagram {engine=mermaid title="Публикация страницы документации"}
flowchart LR
  draft[Черновик в Markdown] --> build(Сборка сайта)
  build --> check{Проверки прошли?}
  check -->|да| publish[Публикация]
  check -->|нет| fix[Правка ошибок]
  fix --> build
:::
```
:::

### Диаграмма последовательности

:::example {label="Схема"}
```markdown
:::diagram {engine=mermaid title="Запрос к API"}
sequenceDiagram
  participant app as Приложение
  participant api as API
  participant db as База данных
  app->>api: GET /v1/pages
  api->>db: Выбрать страницы
  db-->>api: Список записей
  api-->>app: 200 OK
:::
```
:::

### Диаграмма состояний

:::example {label="Схема"}
```markdown
:::diagram {engine=mermaid title="Жизненный цикл страницы"}
stateDiagram-v2
  state "На проверке" as review
  [*] --> Черновик
  Черновик --> review: автор отправил
  review --> Черновик: есть замечания
  review --> Опубликована: одобрено
  Опубликована --> [*]
:::
```
:::

### Модель данных

:::example {label="Схема"}
```markdown
:::diagram {engine=mermaid title="Модель данных сайта"}
erDiagram
  SECTION["Раздел"] {
    string title "название в меню"
  }
  PAGE["Страница"] {
    string slug PK "адрес страницы"
    string title "заголовок"
  }
  SECTION ||--o{ PAGE : "содержит"
:::
```
:::

Остальные 18 типов с примерами из жизни документации — в
[«Галерее диаграмм»](/ru/components/diagram-gallery/).

## Как показывается схема

Сборка кладёт исходник схемы в HTML как текст, а на страницу с диаграммой
подключает Mermaid из комплекта Docara (`vendor/mermaid/mermaid.min.js`, с
сайта, без внешних CDN). Страницы без диаграмм этот файл не загружают, а в
сборку он попадает, только если диаграмма есть хотя бы на одной странице.

В браузере Mermaid запускается с `securityLevel: 'strict'` и темой `default`
и заменяет исходник на SVG. Если JavaScript выключен, читатель видит исходник
схемы. Если Mermaid не смог разобрать схему, исходник остаётся на месте, а
блок получает атрибут `data-docara-render-error="diagram"`.
