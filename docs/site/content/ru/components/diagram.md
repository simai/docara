# Диаграмма

Диаграмма хранит схему Mermaid рядом с текстом статьи, а браузер рисует её
как картинку. Схема меняется вместе с документацией: её исходник лежит в той
же странице и проверяется на ревью как обычный текст.

## Пример

:::example {label="Блок-схема"}
```markdown
:::diagram {title="Публикация страницы документации"}
flowchart LR
  draft[Черновик в Markdown] --> build(Сборка сайта)
  build --> check{Проверки прошли?}
  check -->|да| publish[Публикация]
  check -->|нет| fix[Правка ошибок]
  fix --> build
:::
```
:::

## Разметка

```markdown
:::diagram {title="Понятное название схемы"}
flowchart LR
  A[Первый шаг] --> B[Второй шаг]
:::
```

- Внутри — схема в записи Mermaid. Первая строка называет её тип:
  `flowchart`, `sequenceDiagram`, `gantt` и так далее.
- Подписи держите короткими: длинный текст делает схему широкой.
- Docara не ограничивает тип схемы: работает всё, что умеет встроенный
  Mermaid 11.16.

## Варианты

### Тип схемы

Мы проверили в браузере 22 типа — все они собраны с живыми примерами в
[«Галерее диаграмм»](../diagram-gallery/).

| Задача | Типы Mermaid |
| --- | --- |
| Процесс и поведение | `flowchart` — шаги и развилки, `sequenceDiagram` — обмен запросами, `stateDiagram-v2` — состояния объекта, `journey` — путь пользователя |
| Структура и данные | `classDiagram` — классы кода, `erDiagram` — модель данных, `requirementDiagram` — требования, `mindmap` — интеллект-карта, `treemap-beta` — доли вложенных частей, `block-beta` — блоки по сетке, `packet-beta` — поля пакета |
| Архитектура | `C4Context` — контекст системы, `architecture-beta` — сервисы и группы |
| Планы и история | `gantt` — задачи на календаре, `timeline` — хронология, `gitGraph` — ветки Git, `kanban` — доска задач |
| Графики и сравнение | `pie` — доли целого, `xychart-beta` — столбцы и линии, `quadrantChart` — четыре группы по двум осям, `sankey-beta` — потоки, `radar-beta` — сравнение по оценкам |

Типы с окончанием `-beta` Mermaid считает экспериментальными: их запись может
немного измениться в следующих версиях Mermaid.

:::example {label="Диаграмма последовательности"}
```markdown
:::diagram {title="Запрос к API"}
sequenceDiagram
  participant app as Приложение
  participant api as API
  participant db as База данных
  app->>api: GET /v1/pages
  api->>db: Выбрать страницы
  db-->>api: Список записей
  api-->>app: 200 OK
:::
```
:::

:::example {label="Диаграмма состояний"}
```markdown
:::diagram {title="Жизненный цикл страницы"}
stateDiagram-v2
  state "На проверке" as review
  [*] --> Черновик
  Черновик --> review: автор отправил
  review --> Черновик: есть замечания
  review --> Опубликована: одобрено
  Опубликована --> [*]
:::
```
:::

### Русские подписи

- **`sankey-beta` не рисуется с русскими подписями** — ни с кавычками, ни без
  них. Пишите подписи потоков латиницей.
- **`architecture-beta` и `xychart-beta` принимают русские подписи только в
  двойных кавычках:** `service web(server)["Веб-сервер"]`,
  `x-axis ["Главная", "Значки"]`.
- **В `erDiagram` русские названия сущностей задаются псевдонимом** в блоке
  сущности, а связи пишутся через латинское имя:

:::example {label="Модель данных"}
```markdown
:::diagram {title="Модель данных сайта"}
erDiagram
  SECTION["Раздел"] {
    string title "название в меню"
  }
  PAGE["Страница"] {
    string slug PK "адрес страницы"
    string title "заголовок"
  }
  SECTION ||--o{ PAGE : "содержит"
:::
```
:::

## Состояния

### Как показывается схема

Сборка кладёт исходник схемы в страницу как текст и подключает Mermaid из
комплекта Docara, без внешних CDN. Страницы без диаграмм этот файл не
загружают, а в сборку он попадает, только если диаграмма есть хотя бы на
одной странице. Mermaid весит около 3,6 МБ и загружается один раз на
странице, сколько бы схем на ней ни было.

### Без JavaScript и с ошибкой

Если скрипты выключены, читатель видит исходник схемы. Если Mermaid не смог
разобрать схему, исходник остаётся на месте, а блок получает атрибут
`data-docara-render-error="diagram"`.

### Ограничения

- **Ссылки и обработчики щелчков в схемах не работают.** Mermaid запускается в
  строгом режиме безопасности, поэтому `click` и `href` внутри схемы
  игнорируются. Ссылку поставьте в тексте рядом со схемой.
- **ZenUML не входит в комплект**, схемы `zenuml` не рисуются.

## Доступность

- Схема — изображение с названием из `title`: его слышит читатель с
  программой экранного доступа. Формулируйте название так, чтобы смысл был
  понятен без картинки. Без `title` название общее: «Схема» на русской
  странице, «Diagram» на странице на другом языке.
- Сложную схему перескажите в тексте рядом: последовательность шагов,
  главное решение. Изображение не заменяет объяснение.
- Не передавайте смысл только цветом: подписывайте узлы и стрелки.

## Параметры

| Параметр | Значения | По умолчанию | Что задаёт |
| --- | --- | --- | --- |
| `engine` | `mermaid` | `mermaid` | Чем рисуется схема. Сейчас поддерживается Mermaid. |
| `title` | строка | `Diagram` | Название схемы: подпись над ней и её имя для программ экранного доступа. |
