# Интерактивный пример

Блок показывает рядом готовый результат и его исходник. Читатель переключает
вкладки, проверяет поведение на разной ширине экрана и копирует точный вызов.

## Пример

:::example {label="Пример"}
```markdown
:badge[Готово]{variant=main scheme=success size=1/2}
```
:::

## Разметка

~~~markdown
:::example {label="Название результата"}
```markdown
:badge[Готово]{variant=main scheme=success}
```
:::
~~~

- Внутри — исходник примера в блоке кода: один блок `markdown` или блок
  `html` с необязательными `css` и `javascript`.
- `label` — подпись под примером, как под картинкой: мелкий приглушённый
  текст, длинная подпись переносится. Первая вкладка всегда называется
  «Пример» (строка `examples.example` из `lang.json`), поэтому вкладки
  с кодом видны сразу. Без `label` подписи нет.
- Вместо исходника можно сослаться на общий пример проекта: `id="…"`.
  Смешивать оба способа нельзя.
- Чтобы показать целую страницу сайта и файлы, из которых она собрана,
  укажите её адрес в `src`. Подробнее — в разделе «Пример целой страницы».

## Варианты

### HTML, CSS и JavaScript

Для небольшого самостоятельного интерфейса объедините HTML с необязательными
CSS и JavaScript. Такой пример выполняется в изолированной рамке и не видит
страницу документации.

:::example {label="Интерактивный пример"}
```html
<button class="example-button" type="button">Нажмите</button>
<output class="example-result">Готово</output>
```
```css
:root { color-scheme: light dark; }
body { color: CanvasText; background: Canvas; }
.example-button { padding: .5rem 1rem; }
.example-result { margin-inline-start: 1rem; }
```
```javascript
document.querySelector('.example-button').addEventListener('click', () => {
  document.querySelector('.example-result').textContent = 'Выполнено';
});
```
:::

### Журнал примера

Под примером можно показать журнал: события, которые происходят в примере,
и его консоль. Читатель нажимает кнопки и сразу видит, что пример
сообщает, — без инструментов разработчика. Журнал — часть рамки примера, а
не его содержимого; по умолчанию его нет.

:::example {label="Ссылки" log=click log_console=true}
```html
<div class="links">
  <button type="button" class="sf-button sf-button--default sf-button--primary sf-button--size-1 inline-flex items-center" data-href="/ru/start/"><span class="sf-button-text-container">Руководство</span></button>
  <button type="button" class="sf-button sf-button--outline sf-button--primary sf-button--size-1 inline-flex items-center" data-href="#параметры"><span class="sf-button-text-container">Справочник</span></button>
  <button type="button" class="sf-button sf-button--tonal sf-button--primary sf-button--size-1 inline-flex items-center" data-href="mailto:team@example.com"><span class="sf-button-text-container">Написать</span></button>
  <button type="button" class="sf-button sf-button--link sf-button--primary sf-button--size-1 inline-flex items-center" data-href="ftp://example.com"><span class="sf-button-text-container">Не ссылка</span></button>
</div>
```
```css
.links { display: flex; flex-wrap: wrap; gap: .75rem; }
```
```javascript
document.querySelector('.links').addEventListener('click', (event) => {
  const button = event.target.closest('[data-href]');
  if (!button) return;
  const href = button.dataset.href;
  docara.example.log('navigate', { href, text: button.textContent.trim() });
  if (href.startsWith('ftp:')) {
    console.warn('Схема ftp: браузер её не открывает');
  } else {
    console.log('Переход отменён:', href);
  }
});
```
:::

Журнал включается параметрами примера:

~~~markdown
:::example {label="Ссылки" log=click log_console=true}
```html
…
```
```javascript
docara.example.log('navigate', { href, text });
console.log('Переход отменён:', href);
```
:::
~~~

- `log` — имена событий через пробел, например `log="click sf-button-press"`.
  Docara слушает их на корне примера раньше самого примера, поэтому в журнал
  попадают и события, которые пример останавливает. Строка показывает время,
  имя события и короткие данные: до четырёх полей `event.detail`, длинные
  значения обрезаются многоточием. У события без своих данных, такого как
  `click`, вместо данных — элемент и его текст.
- `log_console=true` добавляет вкладку «Консоль»: `console.log`,
  `console.info`, `console.warn` и `console.error` примера и его
  необработанные ошибки. Предупреждения и ошибки выделены цветом. Этот
  параметр включает журнал и без `log`.
- `log_open=false` — журнал открывается свёрнутым.
- Своя строка из кода примера: `docara.example.log('submit', { plan: 'pro' })`
  — имя и необязательные данные. Вызов доступен в коде любого примера с
  журналом.

Новые строки появляются сверху, счётчик на вкладке показывает, сколько их
(хранятся последние 200). Кнопка с корзиной очищает открытую вкладку, стрелка
сворачивает журнал. Журнал виден и в изолированной рамке, и во встроенном
примере, и в проверке на разной ширине.

Встроенный пример тоже может вести журнал — например, свёрнутый до первого
взгляда:

:::example {label="Встроенный пример" log=click log_open=false}
```html
<button type="button" class="sf-button sf-button--outline sf-button--primary sf-button--size-1 inline-flex items-center"><span class="sf-button-text-container">Нажмите</span></button>
```
:::

Встроенный пример не запускает своих скриптов: скрипт переводит пример в
изолированную рамку. Поэтому вкладка «Консоль» у встроенного примера
показывает консоль всей страницы, а не только примера. В проверке на разной
ширине встроенный пример открывается в рамке, и там журнал получает консоль
самого примера.

Неверное или повторённое имя события и больше 16 имён останавливают сборку
с ошибкой `MARKDOWN_COMPONENT_ATTRIBUTE_VALUE_INVALID`; `log_open` без
`log` и `log_console=true` — с ошибкой `MARKDOWN_EXAMPLE_LOG_REQUIRED`.
Подписи журнала берутся из `lang.json` (строки `examples.log_*`).

### Своя тема примера

Обычно пример показывается в теме страницы, а переключатели темы внутри
примера не работают: тему выбирает читатель для всего сайта. Чтобы показать
сам переключатель темы, добавьте `theme_switch=true` — тогда тема меняется
только внутри рамки примера:

:::example {label="Переключатель темы" theme_switch=true}
```html
<div class="flex flex-col gap-2 items-cross-start p-1 radius-1 bg-surface-1">
  <sf-button-group appearance="segmented" theme-switch size="1/2"></sf-button-group>
  <p class="m-0 text-1/2">Тема меняется только в этой рамке.</p>
</div>
```
:::

- Пример всегда открывается в изолированной рамке и сначала берёт тему
  страницы. Пока читатель не выбрал тему в самом примере, рамка следует за
  темой страницы.
- Переключатели Framework (`sf-button-group theme-switch`, кнопки
  `sf-theme-button`, `SF.Loader.setTheme()`) работают внутри рамки. Тема
  страницы и выбор читателя в настройках сайта не меняются, а выбор в примере
  нигде не сохраняется: после перезагрузки пример снова в теме страницы.
- `preview=inline` с `theme_switch=true` останавливает сборку с ошибкой
  `MARKDOWN_EXAMPLE_INLINE_NOT_ADMITTED`: на странице переключатель сменил бы
  тему всего сайта. Неверное значение — с ошибкой
  `MARKDOWN_COMPONENT_ATTRIBUTE_VALUE_INVALID`.

### Общий пример из проекта

Если пример нужен на нескольких страницах или во всех языках, храните его
один раз в корневой папке `examples/`:

```text
examples/
  utilities/
    animation-duration/
      index.html
      index.css
      index.js
      assets/
```

`index.html` обязателен, остальное — по необходимости. Путь папки становится
идентификатором:

```markdown
:::example {id="utilities/animation-duration" label="Результат"}
:::
```

Docara показывает только существующие вкладки и публикует нужные файлы с
учётом `base_url`. После изменения общего примера выполните полную сборку:
точечная сборка остановится, чтобы не оставить другие страницы со старой
версией.

### Пример целой страницы

Шапку, меню, области макета и настройки раздела видно только на целой
странице. Соберите такую страницу отдельно и покажите её в примере: укажите
её адрес в `src`, а внутри блока перечислите файлы, из которых она собрана.
Каждый заголовок `###` становится вкладкой, под ним — блок
[кода из файла](../code-from-file/), который читает настоящий файл:

~~~markdown
::::example {src="/ru/demonstrator-results/region-header/" label="Результат"}
### page.json

:::code {src="../demonstrator-results/region-header.page.json" lang=json highlight="20-37"}
:::

### Markdown страницы

:::code {src="../demonstrator-results/region-header.md" lang=markdown}
:::
::::
~~~

- Внешний блок открывается четырьмя двоеточиями, чтобы вложенные блоки кода
  закрывались своими тремя.
- `src` — путь от корня сайта, без домена. Чужие адреса не принимаются.
- Внутри блока — только заголовки `###` и блоки `:::code`. Код всегда
  совпадает с файлами, из которых собрана страница.
- В статье страница показывается как экран компьютера шириной 1280 px,
  уменьшенный под ширину колонки. Кнопка проверки ширины открывает её на весь
  экран в настоящую ширину компьютера, планшета или телефона.
- `id`, `preview`, журнал (`log`, `log_console`, `log_open`) и
  `theme_switch` с `src` не сочетаются: показанная страница живёт своей
  жизнью.

Готовый образец — [Шапка с кнопкой действия](/ru/examples/region-header/).

### Способ показа

`preview` выбирает, где показывается результат:

- `auto` — Docara решает при сборке: Markdown и безопасный HTML без своих
  стилей и скриптов встраиваются прямо в страницу, остальное открывается в
  изолированной рамке;
- `inline` — прямо в странице. Если пример требует изоляции, сборка
  остановится с понятной ошибкой;
- `sandbox` — в изолированной рамке, когда важны свои стили, скрипты или
  независимое окружение.

Разметка с адаптивными утилитами (`sm:`, `md:`, `lg:`, `cq-md:` …) при `auto`
открывается в рамке: такие утилиты зависят от ширины окна, а встроенный
пример видел бы только ширину страницы.

:::example {label="Адаптивная карточка" preview=sandbox}
```html
<article class="adaptive-card">
  <strong>Карточка товара</strong>
  <span>Цена и действие меняют расположение на телефоне.</span>
  <button type="button">В корзину</button>
</article>
```
```css
.adaptive-card {
  display: grid;
  grid-template-columns: 1fr auto;
  gap: 1rem;
  align-items: center;
  padding: 1rem;
  border: 1px solid currentColor;
  border-radius: 1rem;
}

.adaptive-card button {
  grid-column: 2;
  grid-row: 1 / span 2;
}

@media (max-width: 600px) {
  .adaptive-card {
    grid-template-columns: 1fr;
  }

  .adaptive-card button {
    grid-column: 1;
    grid-row: auto;
  }
}
```
:::

Выбранный способ и его причина записываются в
`build_<environment>.docara/examples.json` и видны через `inspect page`.

### Что встраивается в страницу

Встроенный пример выглядит так же, как на настоящей странице: выпадающие
списки и подсказки открываются поверх документации. Стили текста
документации на него не действуют. Компоненты Framework, которые использует
разметка, подключаются сами.

Во встроенном HTML допускаются:

- атрибуты `data-*`, кроме `data-docara-*`; значение не может начинаться со
  схем `javascript:`, `vbscript:` или `data:`;
- `id` в kebab-case хотя бы с одним дефисом, не начинающийся с `docara-`;
- атрибут `slot` с простым значением в kebab-case;
- элемент `form` без `action`, `method`, `target`, `enctype` и `name`:
  отправку такой формы Docara отменяет;
- у Smart-элементов `sf-*` — атрибуты, которые закреплённая версия Framework
  объявляет для этого тега.

Никогда не встраиваются атрибуты `on*`, `href`, `src`, `srcdoc`, `style`,
`action`, `formaction`, `form`, `autofocus` и `contenteditable`, а также
элементы `script`, `style`, `link`, `iframe`, `a`, `img` и другие вне
списка. Такой пример остаётся в рамке.

`id` встроенного примера живёт в общем пространстве страницы. Совпадение с
другим примером или элементом оболочки останавливает сборку ошибкой
`MARKDOWN_EXAMPLE_INLINE_ID_DUPLICATE`. Переименуйте `id` или задайте
`preview=sandbox`.

## Состояния

### Проверка на разной ширине

Кнопка с устройствами в шапке примера открывает его на весь экран с выбором
ширины: компьютер — 1280 px или ширина экрана, если он уже, планшет — 768 px,
телефон — 390 px. Меняется настоящая ширина изолированной рамки, поэтому
адаптивные правила срабатывают так же, как в отдельном окне. У встроенного
примера рамка загружается только при открытии проверки, а до готовности
показывается обычный результат. Кнопка выхода и Escape возвращают пример на
место.

### Перенос длинных строк

На вкладке с исходником кнопка включает визуальный перенос длинных строк.
Текст исходника и копирование не меняются. Выбор общий для всех примеров и
блоков кода на странице и сохраняется в браузере.

Обе кнопки можно отключить для сайта, раздела или страницы:

```json
{
  "examples": {
    "fullscreen": false,
    "wrap": false
  }
}
```

или для одного блока: `:::example {fullscreen=false wrap=false}`.

### Только результат

На главной странице и в лендинге код рядом с примером обычно не нужен.
`sources=false` убирает вкладки с исходным кодом и кнопку переноса строк:
читатель видит только результат. Исходник в блоке остаётся, из него
по-прежнему собирается результат. Кнопка проверки ширины остаётся.

:::example {label=Результат sources=false}
```markdown
**Готово.** Сайт собран и проверен.
```
:::

Исходник этого блока:

~~~markdown
:::example {label=Результат sources=false}
```markdown
**Готово.** Сайт собран и проверен.
```
:::
~~~

У примера целой страницы с `sources=false` файлы страницы можно не
перечислять: `:::example {src="/ru/start/" sources=false}` и `:::` на
следующей строке.

### Во всю ширину страницы

На лендинге (`"preset": "landing"`) `layout=wide` растягивает пример от края
до края окна, как широкую подложку. На странице документации пример
остаётся в колонке текста. Так показывают витрину на главной странице или в лендинге;
вместе с `sources=false` остаётся только результат:
`:::example {layout=wide sources=false}`.

### Загрузка

Изолированная рамка загружается, когда приближается к экрану (за 600 px), а
рамка в скрытой вкладке ждёт, пока вкладку откроют. Примеры ниже первого
экрана не замедляют загрузку страницы. Рамка получает тему, направление
письма, шрифты и цветовые токены страницы, поэтому выглядит как окружающая
документация.

## Доступность

- Вкладки примера переключаются стрелками; Tab переводит фокус на кнопки
  копирования, переноса и проверки ширины.
- Рамка примера и её вкладки называются подписью `label`: задавайте понятную подпись.
- Режим проверки ширины — диалог: фокус остаётся в нём, Escape закрывает его
  и возвращает фокус на кнопку.
- Журнал примера — область с подписью «Журнал примера». Его вкладки
  переключаются стрелками, строки объявляются программой экранного доступа
  как журнал, а кнопка сворачивания сообщает, развёрнут ли он.

| --- | --- | --- | --- |
| `id` | строка | — | Идентификатор общего примера из папки `examples/` проекта. |
| `src` | строка | — | Адрес собранной страницы этого сайта, которую пример показывает целиком; файлы страницы перечисляются вкладками внутри блока. |

| `sources` | `true`, `false` | `true` | Вкладки с исходным кодом; `false` показывает только результат. |
| `layout` | `column`, `wide` | `column` | Ширина примера: `column` — по колонке текста, `wide` — от края до края окна на лендинге. |
| `log` | строка | — | Журнал примера: имена событий через пробел, которые записываются с корня примера, например `"click sf-button-press"`. |
| `log_console` | `true`, `false` | `false` | Вкладка «Консоль» в журнале: `console.log`, `info`, `warn` и `error` примера. Включает журнал и без `log`. |
| `log_open` | `true`, `false` | `true` | Открыт ли журнал сразу; `false` — журнал открывается свёрнутым. |
| `theme_switch` | `true`, `false` | `false` | Своя тема примера: `true` — переключатель темы в примере меняет тему только в его рамке, а не на странице. |
