# Синтаксис компонентов

Docara использует два публичных слоя: обычный Markdown и смысловые компоненты
Docara. SIMAI Framework отвечает за итоговый интерфейс, но его внутренние
идентификаторы не нужно писать в документации.

## Обычный Markdown

Заголовки, абзацы, ссылки, изображения, списки, цитаты, inline-код, блоки кода
и таблицы остаются стандартным Markdown. Не создавайте отдельный компонент,
если задача уже выражается им однозначно.

## Компонент внутри строки

Форма `:имя[текст]{параметры}` не разрывает абзац:

```markdown
Работает с :badge[PHP 8.2]{type=tonal scheme=info size=1/2}.

Нажмите :kbd[⌘ K] или :button[откройте каталог]{href=/ru/components/ type=link}.
```

Сейчас так вызываются `badge`, `button`, `icon` и `kbd`. Внутри кода такая
запись остаётся текстом и не исполняется.

## Самостоятельный блок

Блочный компонент использует fence из трёх двоеточий:

```markdown
:::details {open=true}
## Что создаст сборка

Готовый статический сайт.
:::
```

Точные параметры каждого блока показываются на его странице в
[справочнике компонентов](/ru/components/).

Уведомления также принадлежат Docara, поэтому автору не нужно писать JSON или
знать внутренний идентификатор Framework:

```markdown
:::alert {type=warning variant=outlined}
#### Обратите внимание

Проверьте параметры перед публикацией.
:::
```

Допустимые смыслы: `clear`, `info`, `success`, `warning`, `danger`;
оформления: `default`, `flat`, `outlined`. Иконка, фон, граница и доступная роль
собираются автоматически в едином стиле SIMAI Framework.

## Контейнер и вложенные компоненты

Когда родитель содержит дочерние компоненты, внешний fence длиннее:

```markdown
::::grid {columns=3 gap=2}
:::card
#### Markdown

Понятный исходный формат.
:::
:::card
#### JSON

Проверяемые настройки.
:::
:::card
#### PHP

Воспроизводимая сборка.
:::
::::
```

`grid` управляет количеством колонок и расстоянием. `card` отвечает только за
содержимое. Отдельные имена вроде `card-1/3` не нужны.

## Пример с исходным кодом

`example` показывает результат и исходник в одном компактном блоке. Сначала
читатель видит вкладку «Пример», а затем может открыть код и скопировать его.

Для компонентов Docara обычно достаточно одного Markdown-источника:

````markdown
:::example {label=Пример}
```markdown
:badge[Готово]{type=main scheme=success size=1/2}
```
:::
````

Интерактивный пример можно разделить на HTML, CSS и JavaScript. Docara соберёт
их в один результат, но покажет исходники на отдельных вкладках:

````markdown
:::example {label=Пример}
```html
<button id="hello">Нажмите</button>
```
```css
#hello { color: var(--sf-primary); }
```
```javascript
document.querySelector('#hello').addEventListener('click', event => {
  event.currentTarget.textContent = 'Готово';
});
```
:::
````

Markdown нельзя смешивать с HTML, CSS и JavaScript в одном `example`: это два
разных способа построения результата. Для веб-примера обязателен HTML, а CSS и
JavaScript добавляются при необходимости.

## Единые правила параметров

```markdown
{name=value enabled=true ratio=16/9}
```

Имена, типы, значения по умолчанию и допустимые сочетания принадлежат реестру.
Сборка отклоняет неизвестный параметр, неверное значение, незакрытый блок и
недопустимое вложение.

## Что больше не следует использовать

- старый `cta` заменён inline-компонентом `button`;
- старый `features` собирается как `grid + card + icon`;
- `columns` заменяется управляемым `grid`;
- raw-вызовы `ui.*` относятся к внутренней интеграции Framework и не являются
  рекомендуемым форматом авторского контента.

## Где смотреть точный вызов

[Справочник компонентов](/ru/components/) создаётся автоматически.
У каждой записи есть собственная страница: краткое назначение, общий пример,
параметры, компактные примеры вариантов и только действительно важные
ограничения. Результат и копируемый исходник переключаются вкладками. В
справочник попадают только компоненты, которые работают в текущей сборке.

Machine-readable проекция:

```text
/_docara/component-catalog.json
```

## Проверка

```bash
php vendor/bin/docara build production
php vendor/bin/docara verify-static build_production
```

Не расширяйте набор компонентов правкой Markdown или сгенерированного каталога.
Новая возможность получает definition, renderer, fixture, документацию и тесты.
