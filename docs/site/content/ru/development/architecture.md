# Архитектура

Архитектура Docara собрана в одном пакете `simai/docara`. Он отвечает за
командную строку, схемы JSON, наследование настроек, превращение Markdown в
HTML, связь с SIMAI Framework, заготовку нового проекта и статическую сборку.

Папка считается проектом Docara, если в ней есть `docara.json` со схемой
`docara.site.v1`.

## Шаги сборки

:::steps
1. Загрузить и проверить site, section, page и Framework lock.
2. Разрешить наследование и происхождение значений (provenance) каждой
   страницы.
3. Один раз скомпилировать Markdown и Smart-вызовы в типизированный `DocumentIr`
   в памяти.
4. Подготовить страницу, области, секции и блоки из проверенных настроек.
   Превратить эту структуру в Recipe, передать стандартному сборщику
   SIMAI Framework и получить готовый Composition Document.
   Вход PHP-рендерера восстановить из этого проверенного документа.
5. Построить маршруты и каноническую топологию.
6. Получить из одной топологии видимое меню, breadcrumbs и previous/next.
7. Отрендерить содержимое через единый реестр компонентов и общий вход для
   Smart-компонентов, а области макета — через зарегистрированные шаблоны и
   неизменяемые модели представления.
8. Построить из результатов PageBuilder индекс, меню, «хлебные крошки»,
   оглавление, соседние страницы, поиск и машиночитаемый каталог
   компонентов.
9. Собрать кандидатный полный документ через зарегистрированный publisher
   template и передать его общему Framework Asset Planner.
10. По существующему Loader registry определить точные CSS/JS и зависимости
    первого кадра, повторно собрать документ с этим планом и проверить его
    устойчивость по финальному HTML.
11. Записать HTML, CSS с хешем содержимого в имени, квитанции Framework для
    каждой страницы, поисковый индекс и остальные планы.
12. Только после полного успеха транзакционно заменить действующий `build_*`.

:::

## Меню и оглавление

Каноническая структура сайта содержит все страницы, включая скрытые. Меню
строится из неё: скрытые страницы отбрасываются, а их видимые дочерние ветви
сохраняются. «Хлебные крошки» и соседние страницы берутся из той же
структуры, поэтому меню, путь и порядок страниц нигде не расходятся.

Оглавление строится по безопасному HTML из Markdown до подстановки
Smart-компонентов. Каждый заголовок H1–H6 получает уникальный `id`, а
компонент `docara.toc` выводит H2–H6 до глубины `reading.toc_depth`. В
настройках правая область называется `outline`: это постоянное имя области
макета, а не имя компонента.

## Источники и производные результаты

- `resources/component-catalog/native`, `typed`, `smart` и `requirements`
  содержат записи владельцев о возможностях компонентов;
- точная версия в Framework lock и описания компонентов (manifest) определяют,
  какие Smart-компоненты допущены;
- `EffectiveComponentCatalogBuilder` создаёт один проверяемый каталог;
- страницы компонентов написаны в Markdown, а их список строится из
  метаданных результатов PageBuilder, без отдельного генератора страниц;
- `_docara/component-catalog.json`, HTML и диагностическая квитанция — это
  производные результаты, а не второй источник данных.

Техническая запись компонента хранит постоянный идентификатор, контракт и
статус. Текст каждой русской страницы находится в одном Markdown-файле, а
повторяющиеся подписи интерфейса — в `content/ru/lang.json`. Эталонные
примеры пакета и данные других языков не владеют русской страницей.

## Документ страницы

Все страницы проходят через один PageBuilder и общий сборщик Composition
Recipe из SIMAI Framework. Markdown сначала получает типизированное представление
`DocumentIr`, а готовая структура всей страницы — Composition Document.
Это разные документы: первый описывает прочитанный Markdown, второй —
результат сборки страницы вместе с областями, секциями и блоками.
Сборщик макета принимает только типизированный результат PageBuilder: обойти
его сырым HTML или сгенерированной страницей нельзя.

Источник данных — файлы. База данных, редактирование в браузере, роли и
согласования в Docara не входят.

`resources/publisher/templates/page.php` — только внешний шаблон HTML-документа.
Элементы оболочки страницы находятся в зарегистрированных шаблонах
`resources/publisher/components`, а шаблоны, описания и CSS/JS
Smart-компонентов Docara — в `resources/smart`. В `resources/portable`
остаются общая сетка оболочки и поведение всего документа. Сам сборщик не
содержит HTML, CSS и браузерного кода.

## Что нужно для сборки

Для сборки нужны PHP 8.2+ и Node.js 20+. Закреплённая поставка SIMAI
Framework, включая среду выполнения Composition Recipe, входит в пакет Docara.
Node.js запускает общий Recipe resolver один раз на всю сборку; автору не
нужно заводить отдельный frontend-проект. Готовый сайт остаётся статическим:
для его публикации PHP и Node.js не нужны.

Если `node` отсутствует в `PATH`, укажите путь к Node.js:

```bash
export DOCARA_NODE_BINARY=/path/to/node
php vendor/bin/docara build production
```

Необязательная переменная `DOCARA_SIMAI_UI_ROOT` (или `SIMAI_UI_ROOT`)
направляет сборку на другую поставку Framework, которая реализует ту же
спецификацию Recipe. Для обычной сборки она не нужна.

Каждая страница получает отпечатки Recipe и готового Document в отчёте сборки.
Ошибка проверки останавливает создание кандидата и сохраняет предыдущий
результат. [Два варианта страницы](/ru/development/examples/) показывают явную Recipe,
которая выбирает шапку по настройке; для обычных страниц Recipe создаётся
автоматически.
