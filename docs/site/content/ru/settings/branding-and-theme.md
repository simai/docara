# Бренд и тема

Бренд — это логотип, видимое название, необязательная подпись и favicon. Эти
файлы принадлежат проекту: обновление Docara их не заменяет. Шапку собирает
Smart-компонент `docara.brand`, поэтому в настройках не нужны HTML, путь к
шаблону или CSS-классы. Тема — это цвета сайта и светлая или тёмная схема.

## Файлы бренда

Положите изображения в корневой каталог `assets`:

```text
assets/
  logo.svg
  favicon.ico
```

Используйте относительные пути без `..`, обратных слешей и начального `/`.
Символический link вместо файла не допускается. Для SVG задайте `viewBox`,
чтобы изображение масштабировалось на узких экранах.

Допустимы SVG, PNG, JPG, WebP и ICO размером до 2 МиБ. Символическая ссылка,
путь в зарезервированный или выходной каталог и тёмный логотип без основного
отклоняются до очистки предыдущей сборки. Favicon может быть SVG, PNG или ICO.

## Настройка в docara.json

Ниже приведён полный минимальный файл сайта с брендингом:

```json
{
  "schema": "docara.site.v1",
  "title": "Acme Docs",
  "preset": "docs",
  "content_root": "content/ru",
  "framework_lock": "simai-framework.lock.json",
  "default_locale": "ru",
  "base_url": "/",
  "branding": {
    "title": "Acme",
    "mode": "compact",
    "size": "medium",
    "logo": "assets/logo.svg",
    "favicon": "assets/favicon.ico"
  }
}
```

`branding.title` — имя продукта и доступное название ссылки на главную. Оно
обязательно даже в режиме только с логотипом. Один `branding.logo` используется
в светлой и тёмной теме. Поле `logo_dark` добавляйте только тогда, когда у бренда
действительно есть отдельный файл для тёмного фона.

`branding.mode` управляет только компоновкой:

| Значение | Что видно | Когда использовать |
| --- | --- | --- |
| `compact` | логотип и название в одну строку | рекомендуемый вариант для документации |
| `full` | логотип, название и необязательная подпись | когда подпись несёт важный смысл |
| `logo` | только логотип | для узнаваемого знака; `title` остаётся доступным скринридеру |
| `text` | название и необязательная подпись без логотипа | когда графического знака нет |

Режим `logo` показывает в шапке только логотип, без текстового названия;
`title` остаётся доступным именем ссылки на главную. Логотип рисуется через
`<img>`, поэтому для тёмной темы задайте отдельный файл в `logo_dark`.

`branding.label` — короткая вторая строка, например «Документация» или «API».
Она выводится только в `full` и `text`; не добавляйте её только ради заполнения
места. `branding.size` принимает `small`, `medium` или `large` и меняет всю брендовую
группу по шкале SIMAI Framework: высота логотипа — 24, 32 или 40 px, ширина
широкого логотипа следует его пропорциям. Длинное название остаётся в одну
строку и сокращается многоточием, не ломая кнопки header.

Например, вариант только с логотипом:

```json
{
  "schema": "docara.section.v1",
  "branding": {
    "mode": "logo",
    "size": "medium"
  }
}
```

`header` — это область макета, а не компонент. По умолчанию в ней находится
системная секция `docara.header`, которая вызывает Smart-компонент
`docara.brand`. Компонент получает уже проверенный объект `branding`; вставлять
HTML логотипа или путь к template в авторский JSON не нужно.

## Бренд раздела

В `content/api/section.json` можно изменить подпись для каталога и потомков:

```json
{
  "schema": "docara.section.v1",
  "branding": {
    "label": "API Reference",
    "mode": "full"
  }
}
```

Остальные поля наследуются из `docara.json`. Если нужен полностью другой
набор, начните объект с `"$reset": true` и явно задайте все необходимые поля
(см. [наследование и сброс](/ru/settings/levels-and-inheritance/#примеры-наследования-и-сброса)).

## Строка «Сделано на Docara»

Внизу левого меню каждой страницы с меню Docara выводит небольшую строку
«Сделано на» с логотипом Docara высотой 14 px; на английском и других языках
— «Made with» с тем же логотипом. Вся строка — одна ссылка на
<https://docara.simai.io/>, она открывается в той же вкладке. Экранные дикторы
читают её как «Сделано на Docara» («Made with Docara»), та же фраза видна во
всплывающей подсказке.

Логотип встроен в страницу как SVG и берёт цвет из текста строки: надпись —
приглушённым цветом `on-surface-variant`, знак — светлее. Поэтому один и тот же
логотип подходит к светлой и тёмной теме, а при наведении строка темнеет.

Строка закреплена внизу панели меню и отделена от него тонкой линией: меню
прокручивается над ней, а сама строка видна всегда, какой бы длинной ни была
навигация. В мобильном меню строка так же закреплена внизу панели. На
страницах без левого меню (лендинг) строки нет.

Чтобы убрать строку со всего сайта, задайте в `docara.json`:

```json
{
  "branding": {"credit": false}
}
```

Строка исчезает целиком, вместе с линией над ней. По умолчанию `credit`
равен `true`. Это настройка всего сайта: в `section.json` и `*.page.json` ключ
не принимается, сборка остановится с `BRANDING_CREDIT_SITE_ONLY`. Читатель её не меняет, в панели настроек её нет.

## Светлая и тёмная схема, размытие и закругление

Ветка `settings` наследуется и может быть переопределена в `section.json` и
`<page>.page.json`. Её поля принимают только значения из списка:

```json
{
  "settings": {"theme": "system", "modal_blur": "none", "ui_radius": "default"}
}
```

- `settings.theme` — `system`, `light` или `dark`: схема при первом посещении.
  Читатель может выбрать свою в [панели читателя](/ru/settings/reader-preferences/),
  и его выбор важнее.
- `settings.modal_blur` — `none`, `small`, `medium` или `large`: размытие
  страницы за окнами поиска и настроек. По умолчанию `none`: размытия нет,
  остаётся штатное затемнение подложки.
- `settings.ui_radius` — `default`, `medium` или `large`: общий токен
  Framework `--sf-radius--ui`. `default` оставляет значение Framework
  (`--sf-radius-1/3`), `medium` задаёт `--sf-radius-1/2`, `large` —
  `--sf-radius-1`. Меняется один токен, а компоненты используют свои
  переменные с запасным значением из него.

Размытие и закругление задаёт только автор: в панели читателя их нет.
Произвольный CSS из настроек не принимается — стили строит Framework.

## Цвета сайта из одного цвета

Ключ `theme` в `docara.json` задаёт основной цвет сайта, остальные цвета
Docara получает из него:

```json
{
  "theme": {"color": "#0a7d4f"}
}
```

При сборке Docara передаёт цвет генератору темы SIMAI Framework
(`SF.ThemePalette`, тот же расчёт, что у компонента `sf-theme-generator`).
Генератор строит восемь тональных палитр: основную, вторичную, дополнительную,
нейтральную, ошибки, предупреждения, успеха и информации, по 16 тонов в
каждой, — 128 переменных `--sf-<палитра>-<тон>`, — и 98 их полупрозрачных
оттенков `--sf-<палитра>-<тон>--alfa-<n>`, всего 226 переменных. Из них
Framework берёт
все семантические цвета (`--sf-primary`, `--sf-surface`, `--sf-outline` и
другие), поэтому кнопки, ссылки, фон и рамки меняются в светлой и тёмной
схеме сразу. Примеры в рамках получают те же цвета вместе с остальными
токенами страницы.

- `color` — обязательный, `#rgb` или `#rrggbb`, регистр не важен.
- `hue` (0–360) и `chroma` (0–150) — необязательные, это тон и насыщенность
  генератора, как в полях «Тонкая настройка» `sf-theme-generator`. Заданные,
  они важнее того, как прочитан цвет. Если сайт хранит выбор из
  `sf-theme-generator`, перенесите в `theme` все три значения: `value` как
  `color`, `hue` и `chroma`.
- Без ключа `theme` сайт использует собственные цвета Framework, и сборка
  совпадает со сборкой без этой настройки байт в байт.

Основной тон палитры не обязан совпасть с выбранным цветом: генератор берёт у
цвета тон и насыщенность и строит палитру по своим правилам. Для `#0a7d4f`
основной цвет светлой схемы (`--sf-primary-40`) получается `#006d44`.

Полупрозрачные оттенки дают заливки контейнеров, тональные кнопки и фон при
наведении или выборе, поэтому и они следуют выбранному цвету.

Тема общая для всего сайта и задаётся только в `docara.json`, не в
`section.json` и не на странице. Не путайте её с `settings.theme`: там
выбирается светлая или тёмная схема, а `theme` задаёт сами цвета.

Сборка публикует тему одним файлом `_docara/docara-theme.<sha256>.css`,
который каждая страница подключает после своих стилей первого экрана. Ссылку
на этот файл и всё, что нужно для проверки, сборка записывает в
`resolved-page-plans.json` (раздел `build.theme`), а `docara verify-static`
проверяет, что файл совпадает с записью, содержит только эти переменные (тона и их полупрозрачные оттенки) и
подключён на каждой странице.

Ошибки:

- `THEME_COLOR_INVALID` — `color` не `#rgb` и не `#rrggbb`, например `"green"`
  или `"#0a7d4"`;
- `THEME_HUE_INVALID`, `THEME_CHROMA_INVALID` — число вне диапазона;
- `THEME_FRAMEWORK_UNSUPPORTED` — в `simai-framework.lock.json` закреплён
  релиз Framework без генератора темы. Замените lock на
  `vendor/simai/docara/stubs/portable/simai-framework.lock.json`;
- `PORTABLE_INCREMENTAL_THEME_CHANGED` — после смены цвета пересобирается одна
  страница (`build --page`). Соберите сайт целиком: остальные страницы
  ссылаются на прежнюю тему.

## Проверка

```bash
php vendor/bin/docara build production
php vendor/bin/docara verify-static build_production
php vendor/bin/docara serve production --host=127.0.0.1 --port=8000 --no-build
```

Проверьте header, favicon, светлую и тёмную темы, затем остановите preview через
`Ctrl+C`. Если asset отсутствует или выходит за пределы проекта, сборка должна
остановиться до замены прежнего output.
