# SEO и GEO

SEO помогает людям найти сайт в поисковиках. GEO (generative engine
optimization) помогает ИИ-помощникам — ChatGPT, Claude, Perplexity, Алисе и
поиску с ответами ИИ — правильно прочитать документацию и сослаться на неё.
Docara делает почти всё сама, если у сайта задан публичный адрес
[`site_url`](/ru/settings/site-address/#публичный-адрес-site-url).

## Что Docara делает сама

После сборки с `site_url` у сайта есть:

- **Карта сайта** `sitemap.xml` со всеми индексируемыми страницами, их
  переводами и датой последнего изменения (`lastmod`).
- **`robots.txt`**, который разрешает обход и называет карту сайта.
- **Канонический адрес** и ссылки на переводы (`hreflang`) у каждой страницы.
- **Описание** страницы для выдачи и для карточки в соцсетях.
- **Карточка для соцсетей и мессенджеров**: Open Graph и Twitter card с
  заголовком, описанием и картинкой.
- **Структурированные данные** schema.org в формате JSON-LD: сайт, статья
  с языком и датой изменения, путь по разделам (хлебные крошки).
- **Файлы для ИИ:**
  - `llms.txt` — оглавление сайта по соглашению
    [llmstxt.org](https://llmstxt.org/);
  - `llms-full.txt` — весь текст страниц основного языка в одном файле;
  - текстовая копия рядом с каждой страницей: `index.md` рядом с
    `index.html`; страница ссылается на неё тегом
    `<link rel="alternate" type="text/markdown">`.
- **Перенаправление с корня сайта** на основной язык с полным каноническим
  адресом и `noindex`.

Без `site_url` ничего из этого не появляется: сборка для локального
просмотра остаётся прежней.

## Что задать вам

1. **`site_url`** в `docara.json` — публичный адрес сайта. Удобнее задавать
   его в CI на шаге публикации, как в разделе
   [«Адрес сайта»](/ru/settings/site-address/).
2. **Описание каждой страницы** — поле `description` во front matter. Одно
   предложение о том, что читатель получит на странице, до 160 символов.
   Без поля Docara берёт первый абзац, но написанное описание почти всегда
   лучше.
3. **Картинку для соцсетей** — `branding.share_image`. Задавать её не
   обязательно: по умолчанию Docara сама рисует по одной картинке на язык с
   названием сайта, описанием и адресом. Свою картинку задайте файлом PNG
   или JPEG размером 1200×630. WebP Docara тоже примет, но часть соцсетей и
   мессенджеров такую картинку не показывает. `false` убирает картинку. Для
   раздела или страницы значение можно заменить в `section.json` или
   `<page>.page.json`. У каждого языка своя папка контента, поэтому
   картинку легко сделать на языке страницы.
4. **Описание сайта для ИИ** — `discovery.description`: одна-две фразы о
   том, что это за продукт. Без него `llms.txt` берёт описание главной
   страницы.
5. **Доступ ИИ-сборщиков** — `discovery.ai_crawlers`:

   | Значение | Что делает |
   |---|---|
   | `allow` (по умолчанию) | ИИ-сборщики читают сайт, ИИ-помощники могут на него ссылаться. |
   | `deny` | `robots.txt` закрывает сайт для GPTBot, ClaudeBot, Google-Extended, PerplexityBot, CCBot и других сборщиков текста для ИИ. Обычные поисковики по-прежнему видят сайт. |

```json
{
  "site_url": "https://docs.example.com/",
  "discovery": {
    "description": "Документация продукта Example: установка, настройка и API.",
    "ai_crawlers": "allow"
  },
  "branding": {
    "share_image": "assets/share.png"
  }
}
```

## Как писать страницы, чтобы их понимал ИИ

ИИ-помощник читает страницу по частям и цитирует отдельные абзацы. Поэтому:

- **Один заголовок первого уровня** и понятные подзаголовки, по которым
  можно найти ответ.
- **Ответ — в первой фразе раздела**, подробности — после неё.
- **Термины одинаковые на всех страницах.** Новый термин объясните там, где
  он появился впервые, и добавьте в глоссарий.
- **Код и команды целиком**, с языком у блока кода: такой блок копируют без
  правок.
- **Ссылки на соседние страницы** со словами, которые объясняют, куда ведёт
  ссылка, а не «здесь».

Эти правила проверяет [отчёт о качестве](/ru/authoring/documentation-quality/): длину
и наличие описания, заголовки, длинные предложения и термины.

## Корень сайта

Главный адрес сайта (`https://docs.example.com/`) Docara собирает как
страницу-перенаправление на основной язык. Поисковики понимают её, но
серверное перенаправление (код 301) надёжнее. Если хостинг позволяет,
добавьте его — примеры для популярных серверов есть в разделе
[«Размещение на хостинге»](/ru/build/hosting/#перенаправление-с-корня-сайта).

## Даты изменения

Дата страницы — время последнего коммита Git, в котором менялся её
исходный файл. Она попадает в `sitemap.xml` (`lastmod`), в
структурированные данные (`dateModified`) и в
`_docara/page-metadata.json`.

Сборка в CI должна видеть историю Git. В GitHub Actions задайте
`fetch-depth: 0` у шага `actions/checkout`, иначе у всех страниц будет
дата последнего коммита. Если исходники лежат вне Git, дат не будет, и
сборка пройдёт без них.

## Проверка перед публикацией

1. Соберите сайт с `site_url` и выполните `verify-static`: он проверит
   `sitemap.xml`, `robots.txt`, `llms.txt` и каждую ссылку в них.
2. Запустите `docara qa report` и исправьте описания, которые отчёт
   называет пустыми или слишком длинными.
3. Откройте `llms.txt` и `llms-full.txt` в браузере и прочитайте их глазами
   ИИ: понятно ли, что это за сайт.
4. Проверьте карточку ссылки в любом мессенджере или в
   [валидаторе карточек](https://www.opengraph.xyz/) и структурированные
   данные — в [Rich Results Test](https://search.google.com/test/rich-results).
5. Отправьте `sitemap.xml` в Яндекс Вебмастер и Google Search Console.
