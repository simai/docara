# Как устроены компоненты

Страница документации начинается с обычного Markdown. Компонент нужен только
тогда, когда у фрагмента есть отдельный смысл, параметры, состояние или правила
композиции. Все варианты проходят один путь: Markdown и настройки → Recipe →
готовый Composition Document → HTML. Docara создаёт Recipe автоматически,
а общий сборщик SIMAI Framework проверяет структуру страницы.

Типизированный `DocumentIr` нужен Docara для чтения Markdown. Он не заменяет
Composition Document: тот описывает готовую страницу с областями, секциями
и блоками. [Архитектура](/ru/development/architecture/) объясняет этапы сборки.

## Как выбрать

| Задача | Используйте | Где смотреть |
| --- | --- | --- |
| Заголовок, абзац, ссылка, изображение, список, цитата, код или таблица | Обычный Markdown | [Markdown](/ru/authoring/markdown/) |
| Короткая метка, кнопка-ссылка, значок или клавиша внутри строки | Inline Docara | [Каталог компонентов](/ru/components/) |
| Самостоятельный смысловой фрагмент | Блочный компонент Docara | [Каталог компонентов](/ru/components/) |
| Несколько вложенных блоков с ограничениями | Контейнер Docara | [Surface](/ru/components/surface/) и [Сетка](/ru/components/grid/) |
| Готовый проверенный элемент интерфейса из SIMAI Framework | Smart-компонент Framework | [Framework-компоненты](/ru/development/smart-components/#компонент-simai-framework) |
| Компонент конкретного проекта | Smart-компонент проекта или вклад в оболочку | [SDK для разработчика](/ru/development/developer-sdk/) |

## Обычный Markdown

Это основной и предпочтительный формат. Он покрывает заголовки, текст, ссылки,
изображения, списки, цитаты, код в строке и блоки кода, таблицы и сноски.
Сырой HTML на странице запрещён: сборка останавливается с ошибкой
`MARKDOWN_RAW_HTML_FORBIDDEN`. Все
поддерживаемые конструкции перечислены в
[каталоге компонентов](/ru/components/) и подробно описаны в
[руководстве по Markdown](/ru/authoring/markdown/).

## Inline-компонент Docara

Inline-компонент не разрывает абзац:

```markdown
Сборка :badge[готова]{type=main scheme=success size=1/2}.
Нажмите :kbd[⌘ K] или :button[откройте каталог]{href=/ru/components/ type=link}.
```

Поддерживаются `badge`, `button`, `icon` и `kbd`. Неизвестное имя, параметр
или небезопасное значение отклоняются до вывода HTML.

## Блочный компонент Docara

Блочный компонент занимает отдельное место в документе страницы:

```markdown
:::alert {type=warning variant=outlined}
#### Обратите внимание

Проверьте параметры перед публикацией.
:::
```

Имя после `:::` Docara ищет в реестре типизированных компонентов. Точные
параметры и ошибки описаны на странице конкретного компонента.

## Контейнеры и композиция

Контейнер принимает только те вложенные блоки и слоты, которые объявлены в
его описании. Он проверяет `min_children`, `max_children`, порядок и глубину
вложения. Число двоеточий в `::::` помогает записать вложение, но не меняет тип
блока и не обходит проверку.

```markdown
::::grid {columns=2 gap=2}
:::card
### Первый шаг

Проверьте конфигурацию.
:::
:::card
### Второй шаг

Соберите страницу.
:::
::::
```

Для общей контентной полосы используйте [Surface](/ru/components/surface/).
Hero, Showcase и Promo уже оформлены так же, как Surface, и не требуют
дополнительной обёртки.

## SIMAI Framework

Docara принимает только Smart-компоненты точной закреплённой версии, которые
прошли допуск у владельца и проверку в нескольких хост-системах. Описание
компонента, представления, пресеты, слоты, шаблоны, ассеты и оживление в
браузере (hydration) проверяются до вывода HTML. Статус `supported` относится
только к явно принятому компоненту: похожий компонент Framework без допуска
поддерживаемым не становится.

Пример контейнерной композиции: дочерний `ui.list-item` занимает слот
`options` у `ui.dropdown`. Такой вызов собирается только на сайте, чей
`simai-framework.lock.json` принимает оба компонента; в lock этого сайта
сейчас есть `ui.button` и `ui.alert`, поэтому здесь пример только показан.

```markdown
::::ui.dropdown {label="Тариф"}
:::ui.list-item {slot=options type=text value=team label="Командный"}
:::
::::
```

## Компоненты проекта

Проект может держать собственные Smart-компоненты для содержимого и вклад в
оболочку сайта в разрешённых каталогах проекта. Настройки выбирают допущенные
идентификаторы и не принимают функцию обратного вызова, класс PHP или
произвольный путь к шаблону или файлу. Пробный запуск (`dry-run`) записывает
изменения и хеши входных файлов; применение выполняется, только если план и
файлы с тех пор не изменились.

Практический путь: [inspect → scaffold → validate → preview → test](/ru/development/developer-sdk/).

## Где сборка останавливается

Сборка останавливается при неизвестном компоненте или параметре, неверном
вложенном блоке, слоте, их числе, порядке или глубине, незакрытом `:::`,
совпадении пространств имён, несовпадении хеша, выходе за каталог проекта
через `..` или ссылку и попытке передать исполняемый или неразрешённый путь.
Эти проверки выполняются до запуска шаблонов и не ослабляются в режиме
предпросмотра.
