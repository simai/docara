# Файлы проекта

Новый проект состоит из трёх корневых JSON-файлов, каталога с текстами
страниц и служебного файла, в котором Docara записывает, какие файлы
принадлежат ей.

## Дерево проекта

```text
docara.json
redirects.json
simai-framework.lock.json
assets/
  logo.svg
  logo-dark.svg
  favicon.svg
examples/
  utilities/
    animation-duration/
      index.html
      index.css
      index.js
      assets/
content/
  ru/
    lang.json
    section.json
    index.md
    guides.md
    guides/
      section.json
      install.md
      install.page.json  # необязательная композиция только этой страницы
translations.lock.json  # необязательное принятое состояние переводов
.docara/
  engine/
    ownership.json
```

## Настройки сайта, разделов и страниц

`docara.json` задаёт общие параметры и указывает `redirects_file`.
`redirects.json` хранит старые внутренние адреса и страницы, на которые они
ведут; если совместимость адресов не нужна, поле и файл можно не создавать.
Каждый `section.json` действует на свой каталог и вложенные в него. Не
создавайте его, если ветке не нужны собственные настройки.

Файл страницы `<page>.page.json` переопределяет настройки одной страницы и
тоже необязателен: `install.md` соберётся без `install.page.json`, унаследовав
настройки сайта и родительских разделов. JSON нужен, только когда требуется
изменить slug, вид страницы, навигацию, макет или другое поведение именно этой
страницы. `title`, `description`, `tags`, `draft` и `translation_key`
задавайте в front matter Markdown.

Рекомендуемая форма раздела плоская: `content/ru/guides.md` владеет адресом
`/ru/guides/`, а соседний каталог `content/ru/guides/` содержит дочерние
страницы и `section.json`. Сборка понимает и `content/ru/guides/index.md`, но
одновременно создавать обе формы нельзя: сборка завершится ошибкой
`PAGE_SOURCE_ROUTE_AMBIGUOUS`.

Для всех уровней используется одно имя `section.json`, без начального
подчёркивания. Если в старом проекте остался `_section.json`, переименуйте его:
сборка остановится с кодом `SECTION_DESCRIPTOR_LEGACY_NAME`, чтобы настройки
не потерялись незаметно.

## Что создаёт Docara

`build_local` и `build_production` — результаты сборки, а не исходные файлы.
Служебный каталог `_docara` внутри них тоже создаёт сборка.

В `.docara/engine` лежат служебные файлы, которыми владеет пакет Docara, и
их список `ownership.json`. Рядом команда обновления временно хранит
план и проверяемые пакеты для отката. Эти файлы не редактируют вручную.

## Ваши файлы

`content`, `assets`, корневые JSON и ваш `composer.lock` принадлежат проекту:
обновление Docara их не меняет.

- `examples/` — исходники живых примеров. Один каталог примера может
  обслуживать несколько страниц и языков.
- `translations.lock.json` меняется только защищённой командой
  `translations accept`; проверка статуса и сборка его не перезаписывают.
- Корневой `assets/` удобен для логотипов и значка сайта; изображения к
  тексту можно хранить рядом с Markdown. Пути к файлам бренда указываются в
  `docara.json` и проверяются до очистки предыдущей сборки.
