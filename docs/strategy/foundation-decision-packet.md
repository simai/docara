# Фундамент: единый пакет решений перед расширением

Статус: принят владельцем 9 сентября 2026 года явным ответом «согласен — делай» на объяснение четырёх решений простыми словами. Это приложение к [единственному генеральному плану](foundation-plan.md), не новый план и не заявление о готовой реализации. Принятие разрешает реализацию; тесты, совместимость и release gates сохраняются.

Приняты: контейнерная адаптация; конечные семейства subgrid/text-wrap/dynamic viewport; упорядочение загрузки эквивалентных утилит и display-table с сохранением старых классов; сохранение текущей mobile-матрицы и изменение только desktop size=1/3/default (normal) с 1.5rem на 1.75rem. Технические имена ниже реализуют эти решения в существующей модели предсборки, без нового runtime-фреймворка и массовой миграции. Пункт 4 ниже остаётся действующим ограничением, с явным исключением для принятого исправления размерной ячейки.

## Принятые технические решения

Пакет читается совместно с разделами В–Д [актуального плана](foundation-plan.md). Сохранение старых имён/единиц не запрещает принятое исправление размерной ячейки: нужен impact diff. Ранее приняты start/end и spacing=compact|normal|comfortable|spacious с совместимостью старых форм. Углы 30/60 остаются кандидатами вне принятого изменения; публикация требует release gates.

1. **Контейнерные условия отдельно от окна.** Сохранить `sm:`/`md:` для viewport; использовать `query-container` и `cq-sm:` для контейнера. Именованные варианты — `query-container/sidebar` и `cq-sm/sidebar:…`. Набор имён и комбинаций конечный, объявляется в профиле предсборки. В установке потребителя CSS не генерируется. [Синтаксис и проверки](container-conditions-proposal.md).
2. **Один канонический загрузчик для эквивалентных модулей.** Маршрутизировать `col-gap-*` в gap через проверяемую запись совместимости, сохранив старые CSS-адреса column-gap. Проверять эквивалентность деклараций, условий, слоёв и зависимостей; запрещать циклы. Простое удаление второго совпадения без этих проверок не разрешается.
3. **Чистое отображение таблицы без неожиданного оформления.** Добавить `display-table`; старый `.table` сохранить с его фактическим совмещённым поведением и явно документировать. Это не переименование всех display-классов и не новый CSS-компонент `sf-table`. [Обоснование и приёмка пунктов 2–3](utility-ownership-proposal.md).
4. **Эволюция токенов без массовой миграции.** Не переименовывать и не менять единицы существующих публичных токенов в этом этапе. Новые токены описывают назначение, тип, единицу, значение по умолчанию и область наследования. Цвета компонентов опираются на роли, размеры — на существующие шкалы. Менять тему и плотность можно значениями; изменение смысла существующего имени требует отдельного решения о совместимости.
5. **Современное CSS-покрытие — добавочные конечные семейства.** Включить в обязательный реализационный срез subgrid для строк/колонок, text-wrap для обычного текста и динамические viewport-размеры. Точные имена сверять с текущими генераторами до изменения кода; не менять поведение старых grid/height/wrapping классов. Не генерировать автоматически все сочетания состояний, экранов и контейнеров. Новые семейства обязаны проходить CSS↔Loader и изолированный браузерный сценарий.

## Что сохраняется без нового выбора

- Владение исходниками: ui-loader → ui-builder → сгенерированный ui; точные версии у потребителей.
- Уже согласованные обновляемые Chrome/Edge, Firefox, Safari без старых фиксированных WebView.
- Данные, композиция и представление разделены. Не навязывать Docara и backend одну физическую JSON-схему; проверять адаптеры.
- Внешний Smart-шаблон — доверенный код проекта, а не код из контента. Он может менять DOM, но сохраняет объявленные данные, действия, доступность и ответственность за освобождение ресурсов.
- Никакой автоматической замены публичных API и никаких изменений Федерации/AI First в этом этапе.

## Порядок после принятия

Сначала профили/совместимость и их отрицательные тесты; затем новые семейства и сценарии; затем интеграция Smart/Docara и независимого потребителя; после этого точные зафиксированные сборки, проверки выпуска и публикация. Размеры и число запросов измеряются на настоящем результате, а не назначаются задним числом по прошедшей сборке.

Отдельно остаются операционные вопросы: Safari Remote Automation и разграничение dirty backend Admin/UI файлов. Принятие этого пакета не разрешает менять настройки компьютера или забирать чужие незавершённые изменения.
