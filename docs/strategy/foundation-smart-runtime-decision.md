# Общая JS-основа Smart-компонентов

Статус: принятое техническое направление, пилот до release-проверки.

## Решение

SF5 сохраняет нативные Custom Elements (`HTMLElement`) и уже используемый Lit.
Новый обязательный React/Vue-runtime, собственный язык шаблонов или вторая система
реактивности не вводятся. Общий `SfBaseElement` владеет параметрами, обновлением,
событиями, подключением/отключением и внешними шаблонами. Предметная логика,
состояние и разметка остаются у конкретного Smart-компонента.

Повторяемая механика выносится только после доказанного повторения. Пилот использует
три разных по сложности эталона: поле ввода, административное меню и таблицу с
фильтром/диалогом. Перевод всего каталога не является условием выпуска.

## Что изменено в пилоте

- `SfBaseElement` гарантирует освобождение внешнего шаблона даже при ошибке cleanup,
  отбрасывает запоздалую асинхронную загрузку и предоставляет ограниченные
  `onConnected` / `onDisconnected` hooks;
- поле сохраняет нативное значение при обновлении внешнего шаблона и различает
  controlled и uncontrolled режимы;
- меню использует lifecycle hooks общей базы вместо собственного обхода native
  callbacks;
- таблица сохраняет идентичность вложенных Smart-элементов через Lit directive,
  обновляет/снимает props и listeners симметрично, изолирует portal каждой таблицы,
  отменяет draft без изменения применённого состояния и очищает ресурсы при remove.

Публичная HTML/JSON-разметка не требует миграции. Новая обязательная зависимость не
добавлена.

## Воспроизводимое измерение исходников

Команда `node scripts/audit-smart-runtime-pilot.mjs --baseline 4b55b4d2`
сравнивает общий runtime и три эталона с исходным срезом. На текущем рабочем
кандидате:

| Метрика | Исходный срез | Пилот | Изменение |
| --- | ---: | ---: | ---: |
| Поддерживаемый код, строк | 7728 | 7815 | +87 |
| Исходники gzip, байт | 52094 | 53382 | +1288 |
| Native lifecycle overrides | 7 | 2 | −5 |
| Lifecycle hooks | 3 | 5 | +2 |
| Ручные фабрики дочернего элемента таблицы | 1 | 0 | −1 |
| Переиспользуемый Lit child directive | 0 | 1 | +1 |

Рост исходников принят только как стоимость проверяемых гарантий lifecycle,
шаблонов, фокуса и очистки. Он не является аргументом для дальнейшего разрастания
базы. Тест `smart-runtime-pilot-audit.test.mjs` защищает выбранную границу.

## Бюджет финального сравнения

До измерения финальной production-сборки зафиксированы ограничения:

- число сетевых запросов простого Smart и страницы из трёх эталонов не растёт;
- Lit не дублируется в отдельных чанках;
- медиана инициализации и обновления после прогрева не ухудшается более чем на 10%;
- одно изменение публичного параметра не создаёт дополнительного полного render;
- суммарный gzip затронутых production JS не растёт более чем на 3% относительно
  исходного среза без отдельного принятия;
- remove/reconnect не оставляет listeners, observers, portal или запоздалый async;
- DOM identity, value/selection, focus, keyboard, LTR/RTL и темы сохраняются.

Эти пункты ещё должны быть измерены на двух чистых сборках точных source/builder
коммитов. До этого документ фиксирует архитектурное решение и проверенный
source-пилот, но не объявляет release завершённым.

## Правило для следующего Smart

Новый Smart наследует `SfBaseElement`, объявляет публичные props в существующем
registry, использует lifecycle hooks и сохраняет предметное состояние локально.
Подключаемый helper появляется только для второй доказанной реализации той же
механики. Нельзя добавлять глобальную предметную логику, исполняемый JSON или
зависимости сложного компонента ради простого элемента.
