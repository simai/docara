## Parser corrections required by complete coverage

The first all-route typed build exposed two bounded parser gaps:

1. standalone HTML comments could render an empty artifact;
2. a four-character fenced code block was closed by an inner three-character
   fence.

`html_comment` is now an explicit non-visible typed node, sanitized empty raw
HTML remains a non-visible artifact, and fenced code tracks the exact opening
fence length. This fixes the previously broken source example on
`/ru/components/syntax/`; it does not add executable HTML or a new authoring
surface.

## Consumer inventory

- `InlineComponentRenderer` is a Markdown compatibility extractor that
  delegates every content component to the same
  `Declarative\Smart\SmartComponentGateway`; it contains no component-specific
  renderer method.
- `Declarative\Rendering\SmartRenderer` renders already-resolved shell/layout
  plans. Smart admission still occurs through the single gateway; this class
  is not a second public content registry or gateway.
- the coarse declarative `DocumentParser`/`MarkdownNode` contour remains a
  package compatibility and composition test API. `PortableSiteBuilder` does
  not send public page Markdown through it, so it is not a current public page
  owner or rendering path. Removing that package API would require a separate
  compatibility decision and is not silently claimed here.
