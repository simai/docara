## Delivered contract

- a clean `init` accepts only an empty target and installs project-owned
  starter files plus a versioned package-owned `.docara/engine` state;
- `ownership.json` classifies engine-owned, project-owned and generated paths;
- package revision, exact direct dependency versions/references, consumer lock
  hash or source-tree fingerprint, Framework lock snapshot and schemas are
  recorded under the engine-owned state;
- `docara update` exposes mutually exclusive `--verify`, `--dry-run`/`--diff`,
  `--apply` and `--rollback=<id|latest>` actions with stable JSON schemas and
  non-zero failure exit codes;
- apply requires an unchanged canonical plan, desired package state and
  project-marker hash, stages the full candidate, swaps only the package-owned
  directory and records a hash-verified rollback package;
- dirty, unknown, symlinked or conflicting engine state, stale plans and
  damaged rollback packages fail before mutation;
- project-owned Markdown, assets, locale files, `docara.json`, page/section
  settings and Framework project lock are never update targets;
- legacy `init --update` is an explicit refusal with migration guidance, not a
  second implicit updater.

The package intentionally does not ship a mutable root `composer.lock`.
`dependency-lock.json` records the exact installed direct tuple and binds a
consumer-owned `composer.lock` when one exists. An archive/consumer test in the
candidate gate must still prove the full exported dependency graph.
