# M5.6 author workflow and public documentation

Status: PASS

Candidate parent: `2afa35c`

## User-visible result

A new author can edit one existing Markdown owner and rebuild only that public
route. Docara compiles only the selected owner, keeps the accepted navigation,
search and receipts, and publishes through the same PageBuilder. Adding,
renaming or deleting a route is explicitly a full-build operation so every
derived view changes atomically.

README, CLI help and public documentation now describe one lifecycle:

```text
init empty target
update --verify
update --dry-run (or --diff)
review operations
update --apply
update --rollback=<id|latest> when required
build [environment] [--page=/existing/route/]
verify-static
serve
```

`init --update` is documented only as a disabled compatibility guard. Ownership,
stale-plan refusal, project-file preservation, consumer-owned Composer lock,
atomic engine swap and verified rollback are stated consistently.

## Diagnostic correction

The new raw-HTML policy initially mistook inline code such as
`<page>.page.json` for an HTML tag. Inline code spans are now masked before the
authored-tag check. Renderer diagnostics normalize a source inside the project
root to `content/...` and never print the private absolute root. Tests cover
literal code, actual raw HTML and relative `file:line:column` output.
