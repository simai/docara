## Decision

Docara adopts the committed SF5 Smart artifact vocabulary at exact
`simai/bx-simai.main` revision
`d6f90bba6a9a2f30ac41075d62cf51f1014b7e78`. The repository contains:

- a versioned machine-readable normalized contract at
  `resources/contracts/sf5/smart/v1/contract.json`;
- an immutable source ledger with exact upstream file hashes at
  `resources/contracts/sf5/smart/v1/source.json`;
- `Sf5SmartArtifactV1Contract`, which fails closed on identity, strategy,
  hydration, template ID, props and named view/preset artifacts;
- a bounded `LegacySmartManifestV1Adapter` for the six current manifests.

The adapter is transitional input normalization behind the future provider
compiler, not a second renderer or a new public manifest dialect. It preserves
the complete legacy props schema and owner/runtime provenance under the
Docara extension while producing the shared portable core. Project-local
artifacts use SF5 v1 directly.

## Capability decision

The pinned v1 contract can represent Goal 1's required portable capability:
server-static and hydratable strategies, manifest/view/preset/template roots,
props, slots, assets, dependency declarations, metadata and extensions. No
cross-repository contract decision or stop condition is needed.

Current Docara shell components remain explicitly host-bound where their
registered input adapter prepares navigation/outline/preferences data. That
host binding does not change their artifact format or create a second Smart
runtime. The project fixture is portable and contains no host adapter.
