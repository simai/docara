# G1.2 providers, compiler and security policy

Status: `pass_candidate`
Parent: `b5f5e54`

## Result

The existing `SmartRegistry` now has one provider compilation input model:

- `SmartArtifactProvider` exposes ID, priority, namespaces, descriptors and a
  deterministic fingerprint;
- `SmartArtifactDescriptor` carries root-relative artifact records, portable
  manifest, strategy, optional registered adapter ID and provenance;
- `SmartRegistryCompiler` sorts providers deterministically and builds the
  existing registry, not a second registry;
- `ProjectSmartProvider`, `PackageSmartProvider`, `DocaraSmartProvider` and
  `FrameworkLockSmartProvider` encode the accepted precedence 100/200/300/400;
- `FilesystemSmartProvider` discovers versioned SF5 manifest/view/preset/
  template/assets by sorted physical paths.

Namespace ownership is exclusive. Project providers cannot own `ui` or
`docara`; Framework moving refs (`main`, `master`, `latest`, `HEAD`) are denied.
Duplicate providers, namespaces, component IDs and aliases fail closed rather
than being resolved by precedence.

## Security boundary

Provider roots and every file are resolved with `realpath`/`lstat`. Missing,
non-regular, symlinked, hard-linked or outside-root files are denied. Template
and adapter IDs must match a registered identifier vocabulary. Authored data
cannot name a PHP class or filesystem path; only trusted provider discovery can
register a template.
