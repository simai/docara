## Draft release notes

Docara 2 provides one content-first documentation engine: each public page has
one Markdown owner, full and isolated builds share one typed in-memory IR and
PageBuilder, and Smart components use one validated gateway. A clean consumer
can initialize without Node.js, build deterministically and preview/apply/roll
back engine updates without overwriting author-owned content.

Release packaging is repository-owned and deterministic. It emits a minimal
Composer ZIP, content manifest, checksums and SBOM, then verifies the artifact
in fresh consumers. This is a release-candidate note, not a publication notice.

## Operator go/no-go checklist

Before a separately approved publication action:

1. check out exact source revision in a clean clone;
2. run source tests, lint, Composer, schema and graph checks;
3. build twice and compare ZIP, manifest and checksums byte-for-byte;
4. verify the ZIP using `scripts/verify-release-package.php`;
5. install it as dist in a fresh consumer and run init/verify/build/static;
6. confirm the version/tag/package coordinates and approval explicitly;
7. retain the predecessor archive, lock, ownership manifest and rollback test;
8. run post-publication install and smoke checks, then stop on any hash mismatch.

No-go conditions are a dirty/mismatched source revision, artifact hash drift,
license or package-coordinate disagreement, failed consumer install, broken
link/asset, update preservation failure, security finding or missing explicit
publication approval.

## Backup, rollback and smoke

- keep the predecessor and current artifacts plus their manifests/checksums;
- consumer update creates a hash-bound rollback package before mutation;
- rollback must restore the predecessor engine hash while preserving project
  content/config/assets;
- release smoke: install from exact artifact, init, verify, full build,
  representative isolated build, static verification and RU/LTR plus AR/RTL
  browser smoke;
- publication rollback is outside this local goal and needs a separately
  approved registry/release procedure.
