# C3.2 — structured diagnostic parity

Runtime: PHP 8.4.20

## Outcome

`OperationFailureMapper` is the only exception-to-result boundary used by CLI
commands and the optional MCP adapter. It preserves the requested operation and
subject and supplies a safe relative source and JSON pointer, owner, actionable
suggestion and non-empty project/engine provenance. Initialized-project errors
no longer contain `source=null`, empty diagnostic provenance, `unresolved` or a
zero input hash.

The human formatter exposes the same diagnostic source, owner, provenance and
suggestion as JSON. MCP delegates the same application service and returns the
same canonical result; it no longer renames a failed operation to `mcp.tool`.

## Real-command proof

Permanent test `Goal3DiagnosticParityTest` runs actual `inspect smart
project.missing` commands through CLI JSON, CLI human and MCP. It asserts:

- operation `inspect`, subject `smart:project.missing`, exit/isError `2/true`;
- code `SMART_REGISTRY_COMPONENT_NOT_FOUND`;
- source `docara.json#/arguments/id` and owner `docara.application`;
- identical canonical provenance/suggestion and no absolute project path;
- schema rejection for null source, empty diagnostic provenance, unresolved
  engine revision and all-zero input hash.

Application goldens are now regenerated in tests from real commands and only
normalize immutable revision/input hashes before comparison. The former
hand-written `scaffold.stale` fixture was removed.
